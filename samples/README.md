# 演示输入

`showcase-bom.csv` 是一个虚构的 1 套展示柜 BOM，用于练习导入、审核、工艺拆解、分派和报价。尺寸单位为 mm。它并非经过工程验证的生产图纸。

`showcase-front-demo.dxf` 是 ASCII DXF 格式的真实线条/轮廓文件，显示一个展示柜前视示意。带 `CABINET_PART` XDATA 的实体可以导入对应构件；尺寸、材料、数量来自演示属性。文件明确标记 `schematic:true`，不能直接投产。前视外轮廓不是板件展开图。独立实体 ID 与 CSV BOM 不同，二者不能同时当作同一项目的两份新增用量：应使用一个导入途径，或在审核中建立对应关系。

`demo-quote-settings.json` 中的所有单价与费率均为虚构演示值。正式报价必须输入本厂材料价格、工种时薪、损耗和费用假设。未输入单价时系统保留未计价项目，完整总成本和建议售价为空。

`KANPACE-STEP-合成几何演示.step` 由 Open CASCADE 测试代码生成，包含一个旋转 37° 的 1200 × 550 × 18 mm 长方体定义及两个装配实例，其中一处实例名称为“右侧板”。可单独建立**演示项目**，上传后在图纸与构件的 STEP 工程核对里查看候选分组、旋转后轴向／定向外包参考与审批。它没有真实工程图、材料、加工尺寸或生产 BOM；请勿与上面的 CSV/DXF 合并入正式订单，也不要把几何参考值直接作为下料尺寸。

## DXF 明确支持范围

支持 ASCII DXF 的 HEADER/ENTITIES：LWPOLYLINE、传统 POLYLINE/VERTEX、LINE、CIRCLE、TEXT/MTEXT、INSERT 插入点及其 ATTRIB。保留实体句柄、图层、文本和几何。块定义、旋转/镜像块、曲面、样条、弧线几何、动态块及其他复杂实体尚未展开或求解，会列出限制。

只有具有显式构件属性的图形才会变成 BOM。推荐使用 APPID `CABINET_PART`，通过 XDATA 组码 1000 存入 JSON 对象（长 JSON 可拆成多个连续 1000 字符串），例如：

```json
{"id":"WOOD-01","name":"侧板","category":"wood","material":"18mm多层板","length":900,"width":450,"thickness":18,"quantity":2,"unit":"mm","finish":"白色烤漆","revision":"A01"}
```

也支持多个 `key=value` 形式的 XDATA 字符串；支持图层命名 `CABINET::wood::侧板::多层板::18::白色烤漆::2`。图层约定要求 ASCII DXF 的 `$INSUNITS` 明确设置为毫米(4)、厘米(5)、米(6)或英寸(1)。只在明确单位、构件标签、无曲线的轴对齐矩形封闭轮廓下，才可采用轮廓尺寸；其他尺寸从显式属性读取或留空。数量始终来自属性，不能从重复视图数量推断。

CSV 支持中英文表头。`length_mm/width_mm/thickness_mm` 明确采用毫米；如使用 `length/width/thickness`，必须配套 `unit`。JSON 可为构件数组或 `{ "unit": "mm", "parts": [...] }`。尺寸缺失不补数值；类别缺失不凭材料名称猜工种。

DXF 和 BOM 的跨文件零件号、不同版本、不同视图仍需审核关联。同一编号重复出现时，本版保留每条记录及其原始数量，赋予不同内部 ID，并提示“重复编号需确认，整单BOM须明确汇总”；即使两行属性完全一致，也不会自动去重或累加。两份子装配可能各自真实需要一个同料号零件，也可能是同一构件的重复视图，必须由技术员确认整单用量。本版不宣称自动完成任意图纸跨视图去重。
