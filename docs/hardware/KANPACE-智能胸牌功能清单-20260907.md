# KANPACE 智能胸牌功能清单

2026-09-07 · 与 功能与界面规划 PDF（原机资料另存） 配套。

胸牌应让工人看清当前工作、找到对应图纸、用少量操作记录现场情况。一个任务首页常驻，资料和异常按需打开；复杂排程、原始 CAD、3D、图纸识别及 LLM 留在电脑、手机或网关。

**现板为金逸晨 ESP32-C3FH4，4 MB Flash，ST7789 170×320 屏幕，CST816D 触摸，当前已记录的实板版本为 1.5.2-goldenmorning。** 电池容量、充电检测和电量计硬件尚未从本次资料确认，不能承诺班次续航。以下是功能要求与核验边界，并非所有目标已经实现。

## 核验口径

“源码实现”表示当前生产代码已有逻辑；“软件验证”表示有构建、生产 C++ 主机测试、协议或 HTTP 检查；“实板验证”只覆盖实际设备记录证明的操作。内存渲染图不是实板照片，正常重启保留不等于写入过程中突然断电也已通过。

目前实板已记录：固件升级与镜像校验、启动和任务读回、正式 Web 的 USB 连接、两张真实项目图片接收与摘要校验、升级/重启保留、打开图册。**人工触屏正式报工、强制断电中断写入、无线业务闭环和长时间佩戴运行尚未验收。**

## 十二项功能：现状与目标

| 功能 | 当前现状 | 目标要求 |
|---|---|---|
| **1. 任务清楚** | 源码和软件验证已有项目、部件、工序、状态、已做/剩余；未知数量显示“未记录”。只显示最后收到的一条任务。实板任务升级及重启读回已验。 | 首页突出“现在做什么”；一个主要动作，少量必要信息。完整说明进入要点，收到新任务明确提示变化。 |
| **2. 图纸对应** | 任务图按任务、项目、版次匹配；独立项目图册标“预览”，不改变派工。USB 实板两张真实资料接收、校验和保留已验。 | **按真实、已确认版次的施工图指导制造；效果图仅帮助理解整体，不能代替尺寸、工艺或验收依据。** 旧图不能冒充新任务图，预览不代表正式开工指令。 |
| **3. 大字看图** | 常驻任务页、大字工序与分页要点已有；图册施工图/效果图各最多一张，支持1/2/4/8倍与四向移动。图片为Web转换的1280×1792 baseline JPEG，每张≤180000字节。 | 保持大按钮和清晰返回；用真实施工资料验小字、尺寸与放大操作。170×320适合现场查阅，复杂细节转工位大屏；人工观感尚待验收。 |
| **4. 开工与完工** | 开始、暂停、恢复、全部完成已有USB事件流程和软件验证；二次确认间隔至少700ms。设备收到任务不代表开工；业务ACK后才更新事实。需质量放行的任务转Web验收。 | 操作后看清“等待确认 / 已确认 / 未通过”；完成前明确数量。**工人报完工不自动等于质检验收通过。** 实板人工操作到Web记账的完整链路仍需验收。 |
| **5. 分批报量** | **板上已做/剩余目前仅显示Web已登记值，没有部分数量输入器。新增部分完成量只能在Web登记；板端完成事件提交任务全部数量。** | 新增最少操作的分批数量输入，确认本次新增或累计数量的口径，校验不超量、重复提交和版本冲突。规划图里的分批报量按钮必须标“待新增”。 |
| **6. 暂停交接** | 缺料、设备、质量、插单、其他五种原因已有；保留已登记数量及已有交接说明。暂停→原因→确认，恢复前确认条件解除；软件已验。 | 一屏选原因，显示已做/剩余与下一步；补料、维修、质量处理与暂停状态相互关联。暂停本身不能冒充问题已派给处理人。 |
| **7. 板端换单恢复** | **没有板端任务列表、选下一单或自动返回旧单。换单只能由Web重新下发；旧任务历史与进度留在Web，返回旧单也需重下发。** | 后续可增加受派工权限约束的可做任务选择，保留原单交接与进度；换单、返回须核验项目/任务版次及最新状态。PDF中的板端换单属于规划。 |
| **8. 问题处理到人** | 继承的SparkLink只有两块设备之间的求助、接受和双方解决状态；它独立于生产报工，进入该模式会断开路由器。现有预览不能证明当前双板无线现场成功。 | 新增班组求助工单：问题类型→指定班组/负责人→接单→处理→确认解决；有超时与未受理状态。不能把旧双板互动称为完整班组安灯，也不能当紧急报警设施。 |
| **9. 无线联动** | 2.4GHz Wi-Fi连接、图形状态、USB配网和带Bearer的LAN HTTP任务接口已有；历史有联网IP读回。**Wi-Fi亮弧只说明连上AP，不代表业务成功；无线HTTP派工未完整实测，无线报工和无线传图尚未实现。** | 完成工厂局域网中的真实任务下发、图片、报工和业务ACK；分别显示网络状态与待确认状态。弱网、VPN、重连和多设备情况均需验证，当前HTTP也不具备TLS加密。 |
| **10. 断网不丢** | 事件先存LittleFS再通过USB重放；**队列最多8条，同一任务最多1条待确认**，使用同一event_id重试。等待时不能叠加该任务动作，不能离线连续开始→暂停→完成。持久化异常和重放已有软件测试。 | 保留“本机已保存、待同步”状态；队列满或存储失败明确提示。补无线后仍沿用业务去重与ACK，不把收包当记账；真实拔插、掉电与恢复需验收。 |
| **11. 工厂保密** | 后台已有正式投递、设备/任务/版次及负责人检查；账号与独立实例隔离有软件/HTTP验证。板端任务和图片持续保存在Flash；UI隐藏字段不等于清除。现有LAN HTTP为明文，设备换绑、挂失及清理尚未验收。 | **通信需认证与加密，设备只缓存当前工作所需的最少资料；现有明文LAN不能算完成交付。** 明确设备归属，换人/归还/挂失/停用可追溯，轮换凭据并核验清理；离线丢失设备不能承诺立即远程擦除。 |
| **12. 续航升级** | 电池方案未知；当前背光启动固定点亮，未见电量采样或休眠实现。USB只写应用分区升级并保留数据已有实板记录。当前为3MB单app分区，**没有双槽OTA回滚实现**。 | 核实电源硬件后再做电量、低电提醒、背光超时、唤醒与班次续航；先保留管理员USB维护。OTA另行设计分区、签名、回滚和断电恢复，不能直接承诺远程无损升级。 |

## 三类界面的复用规则

1. **当前任务场景**复用现有常驻首页、已做/剩余、状态主按钮和等待确认。分批输入是新增能力，应在图上标“规划”；示例数量不应被当作现场实时数据。
2. **图纸与效果图场景**复用已有图册、缩放和返回结构，资料按需打开。明确项目、图种、任务/预览身份；现有线框示意是测试样本，不能替代客户原图。说明页仍可复用现有要点分页，不再增加常驻菜单。
3. **缺料暂停后换任务场景**复用已有暂停原因和二次确认；先显示业务是否确认，再呈现规划中的换单选择。现有演示若要返回旧单，须由Web重下发，不能只切画面就声称业务已恢复。

网络详情、确认和错误说明是短暂子页；成功返回首页。当前BOOT返回和长按旧协作含义不能在规划中悄悄改用。沿用固件渲染图须标“同源渲染预览”；新增界面须标“规划”，不能写成实板已验收。

## 三类生产现场的适配

| 现场 | 任务识别 | 作业资料的重点 |
|---|---|---|
| 展柜工厂 | 项目、柜号、板件或五金件、工序、数量 | 材料厚度、封边面、孔位、表面要求；施工图与原效果图 |
| 机械设备装配厂 | 设备号、组件、零件号、装配步骤 | 装配位置、紧固扭矩、检验点、试机门禁；源装配图 |
| 工程现场 | 项目、楼层区域、工作面、专业工种 | 施工版次、前序移交、材料到位、现场验收与交接要点 |

三类现场沿用“看任务、看资料、报进度、暂停交接”的同一操作结构。工种、前序、可开工条件与验收规则由本厂 Web 配置并复核，不让工人在胸牌上编辑工艺或排产。工人只见自己的任务；老板、计划员和现场管理者在 Web 查看交付、缺料、异常与成本。

## 交付验收要求

1. **实板易用**：真实长工序、交接和原图通过人工读图、缩放与触控验收；记录光照、常用手套和误触表现。
2. **图纸匹配**：任务、项目、版次和预览身份正确；换版或中断上传不混图，错误摘要不显示成功。
3. **报工数量**：人工完成操作到Web记账；测试卡和质量门禁仍有效。新增分批报量覆盖超量、误输、重复提交及版本冲突。
4. **暂停换单**：暂停保留数量与原文，返回旧单不丢进度；当前先验Web重下发，板端任务选择单独标未交付。
5. **真实无线**：脱离USB后验证实际任务、图片与报工ACK；Wi-Fi仍连接但服务不可达时，不得显示业务成功。
6. **故障恢复**：覆盖拔插、ACK丢失、重启、写入中断电、8条容量和同任务1条限制；同一事件重试不重复记账、不静默丢失。
7. **保密交接**：验证通信认证与加密、最小资料缓存；用隔离数据验错设备/负责人/工厂、停用换绑、凭据不回显及归还清理。明文LAN和Web权限不能替代这些验收。
8. **续航升级**：确认电源硬件后测低电、待机、弱网和实际续航；USB升级保留任务/图片/配置。OTA仅在分区与失败回滚专项通过后交付。
