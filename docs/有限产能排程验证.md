# 有限产能排程验证

范围：`scheduling.py`，隔离 SQLite 与真实类型的测试资源，不连接硬件，不使用正式客户数据。

排程是分钟粒度的确定性启发式模拟，并非全局最优 APS 求解。班次从每日 08:00 开始，依据人员和工作中心的有效容量分配分钟；同一道工序必须同时占用其人员与工作中心。当前支持最大16小时有效班次。

## 本轮验证与修复

1. 不同人员和不同工作中心可以并行；同一人员或共享工作中心必须串行。
2. 汇合节点等待所有分支中最晚可转序时间。
3. 准备时间占用人员和工位；工后等待释放资源，但仍限制后序开始。
4. 未知加工时间不会自动补零；显式人工分钟覆盖后才能排入。
5. 缺料没有到料日期时不能排入，有预计到料日期时可作条件排程，并提示实际开工仍须齐套。
6. 无效工程版本、未发布、已关闭、演示人员和跨厂人员均不能进入真实排产。
7. 原有人日计划冻结并占用跨项目产能；新模拟不改原计划。
8. 新方案保存精确 `minute_segments`。再次模拟时复用精确占用，保留工后等待的 `ready_at`；防止冻结排程被错误搬回08:00，或把多日固化压缩为次日可转序。
9. 不足一分钟的等待向上取整，避免保存后提前转序。
10. 插单影响包含分钟推迟／提前，也包含原本可排但被挤出模拟范围的任务及新排入任务。
11. 指纹覆盖任务、人员、工作中心、原计划、工作日历、材料、异常和开工检查；任何相关数据变化后旧方案不可采用。
12. 采用方案不派工、不更新实际任务状态；重复采用返回同一组计划，不重复预约产能。

`tests/test_scheduling.py` 共15项通过。

## 原有人日编辑器的集成要求

分钟方案拥有 `scenario_id,start_at,end_at,ready_at,minute_segments,setup_minutes,wait_hours`。不能用原人日编辑器直接改日期和工时并丢弃这些字段。齐套确认与说明可以单独更新；更改时间安排应取消并重新模拟，或者用能重校全部相关分钟依赖和资源占用的专用编辑接口。
