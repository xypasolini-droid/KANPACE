# R34 · 按订单文件夹生成可追溯拆单草稿

展柜订单可以上传整个文件夹，在「施工图与拆单」选择已上传的 XLSX 下单清单，生成柜体记录、图纸关联、工程明细及工种草稿。入口为 `POST /api/projects/{id}/order-packet`，必须提供本项目 `master_document_id` 和当前 `expected_revision`。其他行业继续使用原有行业工作包。

## 已实现

- 按 Excel 明示表头读取名称、尺寸、单位、数量；忽略隐藏旧工作表，仅按实际合并区域继承材料说明。
- 保留整柜长、宽、高及弧长原文；不把柜高当板厚，不执行公式，不把空库存或未知工时当零。
- 读取 WPS `DISPIMG` 的工作簿内图片，保留工作表和单元格依据，供柜体效果核对。
- 关联柜号对应的导出工程 PDF 页，提取明确装配表行及具名的「尺寸＋材质＝数量」料单表达式。遗漏行和嵌套用量仍需技术复核。
- PDF 文字相同后进一步核对渲染像素；只有像素一致才折叠重复页。左右件、不同弧长、同名但不同图号的对象仍分开。
- 保留订单文件相对路径。同名零件分属不同柜体时分别留存；相同内容记录来源别名，其中一个别名换版不会注销其他柜体的来源。
- 文件夹导入同时收集明确效果图目录中的图片；原生 CAD 单文件上限为 64 MiB，其他文件继续保持 20 MiB，避免大型 DWG 无法留存。
- 重复拆解保持幂等；补传文件后允许重建未执行草稿；保留同清单的核对意见；已执行任务不会被覆盖。
- 工程明细可直接打开对应 PDF 页；材料与做法原文一起展示；真实疑问默认展开；整单拆解与 AI 核对入口合并到同一操作栏。
- 胸牌图片候选保留零件与 PDF 具体页的关联，按需生成现有胸牌协议要求的 JPEG。

## 当前边界

这是一套基于本地文件结构、文字和明示字段的提取规则，不是能理解全部 CAD 几何的通用视觉模型。`.SLDPRT`、`.SLDASM`、`.SLDDRW` 和 `.DWG` 原件留存；本功能不解析其原生几何。以已导出的 PDF 为图纸依据。扫描件和乱码文字需要 OCR 或人工逐页确认。XLSX 公式结果不作为已确认数量。

生成的部件 `draft_only=true`、任务 `status=draft`，工时为未知；必须细化并复核生产 BOM 才能发布。未提供真实生产排程、人员、库存时，不产生工厂承诺交期或实际采购订单。原生文件数量只作为能力说明，不逐文件扩充待核对事项。

本轮以独立本地测试数据库完成三份真实订单的资料导入和草稿核对，并用来源可核对的局部零件回放排程、暂停、恢复、标签、交接及模拟发货。回放人员、库存、日期、工时与检验记录为测试输入；没有向实体设备下发生产指令。

## 验证

`tests/test_order_packet.py` 验证隐藏表、合并区域、公式、弧长、具名料单、路径、幂等、更新草稿、生产记录保护及项目归属。原有 API、订单草稿、排程、物料、每日流程、项目派工和胸牌图片测试一起回归；前端图片隔离和状态保留测试继续通过。私有实单、截图及测试报告置于独立工作目录，不进入可分发源码。

### 页面卡顿反馈后的刷新改进

重新获得浏览器焦点时，合并短时间的重复触发；最近 30 秒已成功读取数据时不再次自动刷新。打开任一图纸弹窗、填写输入项、上传文件或已有数据请求进行中时跳过焦点刷新，减少页面替换干扰点击。手动刷新和业务保存后的刷新保持即时。读取失败会释放请求状态，允许后续重试。

`tests/test_focus_refresh.cjs` 覆盖以上行为、失败恢复及设备专用刷新路径；另外三组图纸前端回归继续通过。已在内置浏览器验证任务草稿页签、拆单弹窗和 PDF 翻页。当时未能稳定重现用户描述的点击无响应，以上改进针对重复刷新风险；后续录屏定位的问题及修正如下。

### 录屏复现：效果图缩略图无法切换

录屏中页面可以滚动，但点击其他效果图后大图始终停在第一张。已在用户使用的 Chrome 页面复现：旧订单清单提取出的 WPS 图片没有 `id`，点击处理器保存了 `undefined`，选图逻辑随后把第一张同样没有编号的图片判为选中。

- 新生成的清单图片和 PDF 页具有由项目、源文档和图片位置派生的稳定编号；编号不依赖列表顺序或显示标题。
- 读取旧订单图片时补全编号，不重建拆单、不写回原订单记录，已有资料无需重新导入。
- 前端兼容无编号图片，用已校验的本地图片 URL 保留选择；列表重排、服务器补充编号及重复图片归并后仍能找回对应图片。
- 工程图分组也使用同一选择键，避免缺少编号时把不同 PDF 页错误合为一页。
- 更新图片脚本版本，刷新页面即可载入修正。

`tests/test_project_visual_selection.cjs` 通过真实的委托点击处理器与大图 HTML 检查复现缺陷：修改前断言失败（预期形象板，实际第一张柜图），修改后通过，并覆盖空编号、列表重排、图片去重别名、切换项目及不同工程页。订单包测试新增旧记录只读兼容与 PDF 页编号用例。此次相关验证为 14 项订单包测试、27 项胸牌图片后端测试、7 组前端测试全部通过。

Chrome 实际页面验证完成：11 张清单效果图逐张切换；选中图片能打开对应放大窗口；窗口从第 4 张切至第 5 张；施工 PDF 从第 1 页翻到第 2 页；进入任务草稿再返回图纸页后保留选图。8765 与 8776 均已加载本次修正。

## 依赖和商用说明

生产模块 `order_packet.py` 新增逻辑使用 Python 标准库、项目已有 Pillow 与外部 Poppler 工具，不新增商业 CAD SDK 或带独立模型授权的服务。沿用项目既有第三方许可与部署要求。本次研究用的 PDF / XLS 阅读辅助包只装在私有测试目录，没有成为本模块运行依赖。
