# KANPACE 表格互联与实绩校准

## 文件互联

`file_exchange.py` 提供 CSV/XLSX 上传首读、字段映射、业务预览、差异校验、幂等应用、业务数据与应用回执导出。原文件保留原始字节并记录 SHA-256，不改写源文件，不执行 Excel 公式。文件中 `status/完成/已发货` 不能直接映射为系统执行状态。

调用方在一个 SQLite 写事务内执行修改，所有异常回滚。业务预览用 SAVEPOINT 调用真实业务校验，再回滚模拟写入；预览只保存独立审阅记录，项目、人员、材料、任务、事件均不被模拟结果修改。

### API 与 Python 函数

| API | 函数 | 说明 |
|---|---|---|
| GET `/api/exchange` | `build(store,con)` | 预览历史与字段目录 |
| POST `/api/exchange/preview` | `prepare(store,con,data)` | 首读或映射预览 |
| GET `/api/exchange/{id}` | `get_preview(store,con,id)` | 预览详情与应用回执 |
| POST `/api/exchange/{id}/apply` | `apply(store,con,id,data)` | 版本检查后原子提交 |
| GET `/api/exchange/export` | `export_data(store,con,entity_type,format,project_id,factory_id,preview_id)` | bytes、filename、content_type |

上传参数为 `filename,content_base64,entity_type,mapping,source_system?,sheet?,header_row?,defaults?`。`mapping={}` 时只返回表头、工作表清单与前八行样本；此时不创建预览记录。之后把规范字段映射到原表列名，例如：

```json
{
  "entity_type": "projects",
  "source_system": "本厂Excel订单",
  "mapping": {
    "external_key": "业务订单号",
    "name": "店铺名称",
    "due_date": "承诺交期"
  },
  "defaults": {"factory_type": "cabinet"}
}
```

必填项与列标题以接口 `field_catalog` 为准。可用于：

- projects：原系统订单号、项目名、客户、交期、数量、工厂类型与工厂ID；新项目始终为 draft。
- people：原系统员工号、姓名、岗位、技能、明确工厂班组、每日可用分钟；未知容量保留 null，不使用演示人员。
- materials：原系统需求行号、项目、关联任务、名称、需求数量、**已验收并预留数量**、单位、预计到料日期、供应商；该字段不能以单纯“到货数量”冒充验收可用数量。
- progress：原系统唯一报工事件号、任务ID、累计完成数量、说明；必须为已发布且执行中的有效任务，沿现有报工动作检查前序、人员及数量。登记到总数量也不会自动完成验收或关闭任务。

预览行包含 `action=create/update/skip/error`、原行号、单元格位置、目标ID、预期版本、规范数据、字段前后差异、错误。任何错误行都会阻止整个预览应用，避免静默部分导入。修正原表或映射后重新预览。

### 唯一编号与版本

关联键为 `(source_system,entity_type,external_key)`，不按相似项目名、客户名或订单尾号自动合并。首次绑定已有记录可以显式映射 `target_id`；以后不能把同一外部编号悄悄重绑定到其他记录。

预览记录目标完整指纹、关联行指纹，以及相关项目、物料关联任务和组织资源的上下文指纹。预览后有人编辑同一记录，应用会拒绝并要求重新预览。不同预览并发导入同一外部编号，也不会生成重复项目。相同预览再次应用返回原回执。

报工还按来源事件号与内容指纹幂等：复制文件不会重复计账，重复事件号但数量或说明不同会报错。后续新报工须使用新事件号，不能篡改已经确认的旧事件。

日期必须有明确年份。XLSX 支持实际工作表单元格，不依赖不可信的 worksheet dimension；映射值包含公式时拒绝应用，要求在副本中粘贴已核对数值。CSV 支持 UTF-8 和 GB18030。导出 CSV 防止公式注入，XLSX 以字符串保存外部编号，保留前导零。

材料的关联任务ID支持顿号分隔，导出与回导保留全部关联，空日期和空归属维持原空值语义。

导出支持独立业务表和按 `preview_id` 的回执文件，包含源文件、工作表、行号、外部编号、KANPACE编号、操作及结果；不自动改动客户原有 Excel 布局。

## 实绩校准

`calibration.py` 只读取真实完工任务、完整闭合的 `work_sessions` 和任务关联的 `actual_costs`。配置或推估工时不进入样本。

- GET `/api/calibration?factory_type=&factory_id=`：`build(store,con,factory_type,factory_id)`。
- POST `/api/calibration/estimate`：`estimate(store,con,{task_id,quantity?,percentile:'p50'|'p80'})`。

分组维度包含行业、工厂、工种、工序、计量单位、开工/验收要求及操作要求。不同工厂或不同精度要求不混为一套标准。每个样本保留任务、项目、人员、完整计时段、完成数量与实际活跃分钟，暂停等待不计为加工分钟。

拒绝演示数据、未完工任务、无实绩计时、未闭合计时、计时相互重叠、首尾记录不完整及单次超过24小时的未核对计时。历史任务没有新计时依据就没有样本，不能从原估计工时倒推真实记录。版本迁移的任务拷贝不会重复算同一实绩。

返回每对象 P50/P80 分钟、样本量、独立项目数、区间以及排除原因。少于3个样本标明样本不足；少于10个或不足3个项目为有限样本。无相同工序实绩返回 null，不显示虚假零工时。

成本区间是任务关联的**已记录成本 / 已完成工作对象数量**。未完整归集的费用不能假定为零，区间不能直接等同完整报价或毛利。接口给出参考值与原成本记录，用户核对后才可通过新模板版本或报价编辑应用。接口本身不更改任务、模板、排程或报价。

## 验证

- `tests/test_file_exchange.py`：15项隔离测试，覆盖 CSV/XLSX、前导零、公式保护、预览不写业务、重复/差异/并发预览冲突、实际物料调用、真实任务报工、复制文件幂等、多任务物料往返、相关工程版本指纹及回执导出。
- `tests/test_calibration.py`：13项隔离测试，覆盖只取实际活跃段、剔除暂停、估计工时不参与、三类不完整时间、工厂/单位/验收隔离、成本归属、无样本和迁移不重复。

## 按项目留出的误差验证

每个工序组增加 `validation`，顶层增加 `validation_summary`。采用按时间最近的完整项目作为留出集，训练数据来自其他项目，并且完成时间须早于留出项目的最早样本。同一项目不会拆成一部分训练、一部分测试；后发生的数据也不会用于预测较早的测试对象。

至少需要3个独立训练项目和1个留出项目。样本不足时返回 `insufficient_projects`，虽然项目够数但时间交叠导致有效训练历史不足时返回 `insufficient_history`；两种情况下误差、覆盖率均为 null。

可验证时返回训练／留出样本量与项目数、项目ID、时间截点，以及每道留出工序的 P50 预测分钟、实际分钟、绝对误差、相对误差、P80预测分钟和是否覆盖实绩。汇总提供 `mae_minutes`、`mape_percent`、`p80_coverage`。P80覆盖率是已有留出结果的实际比例，不是对未来承诺80%准确。该验证不更改任务、工艺标准或报价。

校准模块现有13项测试，新增验证整项目隔离、时间穿越阻断、同项目多行不能冒充独立样本、P50误差和P80覆盖正确计算。

正常生产与返工以 work_kind 分开归组，返工耗时不会降低或拉高普通工序的标准周期。
