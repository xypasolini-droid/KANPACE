# KANPACE 本地排程与排料引擎

本模块是可选本地优化组件。核心 Web 仍只依赖 Python 标准库；OR-Tools 在 `.venv-optimization` 中独立执行，PackingSolver 使用官方 C++ 命令行。两个引擎不修改工序状态、人员分派、库存、图纸版本或成本台账。

## 排程的短事务接法

```python
import optimization_engines

# 用现有权限校验得到的客户 Store；先短读事务提取一致快照。
with store.connect() as con:
    prepared = optimization_engines.prepare_schedule(store, con, data)

# 不持有数据库写锁，等待有时限的本地 CP-SAT。
scenario = optimization_engines.solve_prepared(prepared)

# 开启现有短写事务后，重新核对整个生产快照指纹。
with store.connect() as con:
    con.execute('BEGIN IMMEDIATE')
    result = optimization_engines.persist_schedule(store, con, scenario)

# 用户审核后仍调用 scheduling.apply；该接口再次核对版本与指纹。
```

`data` 沿用 `scheduling.preview` 的 `start_date`、`horizon_days`、`factory_type`、`task_ids`、`rush_task_ids`、`overrides`、`name`、`note`。新增 `time_limit_seconds`（1–60，默认 10）、`allow_fallback`（默认 true）、`non_interruptible_task_ids`（可选且必须处于本次可排范围）。

`solve_prepared()` 返回普通 scenario 字典，含 `rows`、`unplaced`、`frozen_plan_ids`、`summary`、`impact`、`fingerprint`，以及：

- `engine.requested`、`engine.used`、真实 CP-SAT `status`、`version`、求解时间与可用的 objective/bound。只有 `FEASIBLE` 或 `OPTIMAL` 才读取解。
- `validation`：独立整数算术校验，核对工时、日历、冻结占用、负责人/工位冲突、前置等待、不可中断规则与已排/未排的完整覆盖。
- `comparison`：相同快照的原启发式及新方案统计、变化数量、总延期分钟、优先级加权延期分钟与是否不劣于基线。

`persist_schedule()` 在快照改变时返回 `409 scenario_stale`，不会保存过期方案。`schedule_preview()` 是三步的便捷组合；HTTP 路由应使用分段接口避免长时间持有写锁。

`schedule_advice(store, con, data)` / `schedule_compare(...)` 返回 `status=advice` 的相同字典，不写入任何 scenario、event、plan，可供本地助手调用。

模型保持当前负责人及工作中心，不自动重新分派。它按现有每周工作日、08:00 起算和每日有效容量建立可用窗口，排除冻结分钟；一项工序可在不同空闲窗口间分段，同一个窗口内一个连续片段。选择 `non_interruptible_task_ids` 后该项仅能占一个片段。可变班次/节假日仍取决于 KANPACE 的源日历能力，没有伪造未维护的班次。准备时间计入占用；工后等待释放人机并约束后序，与现有模拟一致。物料仍采用当前缺口及预计到料门禁，没有声称实现跨订单共享库存 MRP。

默认目标优先尽可能安排更多合格工序，随后考虑插单/优先级、延期和完成时间。超时/失败可明确回退为 `used=KANPACE heuristic`；不会把回退结果标成 OR-Tools。显式不可中断规则不允许退回不支持该规则的旧模拟。开启回退不表示可以自动采用方案，现有确认发布仍然必须经过业务检查。

## 排料输入

仅接受人工已确认的同材质、同板厚、同纹理组，单位毫米，最多两位小数。

```json
{
  "dimensions_confirmed": true,
  "material": "审核后的板材编号",
  "thickness_mm": 18,
  "grain": "none",
  "kerf_mm": 5,
  "trim_mm": 10,
  "stock": {"width_mm": 1000, "height_mm": 1000, "quantity": 5, "cost_per_sheet": 120},
  "items": [{"id": "panel_a", "label": "侧板", "width_mm": 480, "height_mm": 480, "quantity": 4, "allow_rotate": false}],
  "baseline_sheet_count": 2,
  "time_limit_seconds": 5
}
```

调用 `packing_preview(data)`，返回 `engine`、`input_summary`、`layouts`、`summary`、`validation`、`baseline_comparison`、官方 `certificate_csv` 与 `solver_report`，不访问业务数据库。

`grain` 为 `none` / `width` / `height`；有纹理时不允许 90 度旋转。每项可携带 material/thickness_mm/grain，但必须与原板及当前组一致。不得从未审核 OCR、成品外形或未展开钣金直接生成这些参数。`dimensions_confirmed` 表示发起人在当前订单中已完成尺寸复核，不代替工程审核权限。

`layouts[].pieces` 提供原板左下角原点的 `x_mm/y_mm/width_mm/height_mm`、零件编号、名称及旋转标记；`leftovers` 是官方切割树留下的空白子板。`cut_nodes` 与 CSV 保留求解器内部的 0.01 mm 整数坐标，保留父子树可供追溯。界面画图使用 `pieces` 的毫米坐标。

使用实际 `packingsolver_rectangleguillotine`，选择 3 阶 non-exact 齐头切、原始锯缝和裁边、HiGHS 后端；不会输出自编排列冒充引擎。独立校验包括数量、尺寸、旋转、锯缝、边界、板数、父子树与贯穿直切。有限时搜索一律标 `FEASIBLE_VALIDATED`，不自行宣称最优。板数不足或任何零件遗漏会拒绝方案。

`material_cost` 仅为原板单价乘实际板数；未填单价时为 null。未填用户原方案板数时不虚构节省。剩余空白区域不等于已经验收可再用的库存，不自动登记余料价值或采购订单。Web 必须沿用现有财务/报价权限后才能返回含金额的结果。

## 安装与许可证

入口：`python3 setup_optimization.py --python /path/to/python3.11`，或指定 Python 3.12。需要本机 C++ 编译器与 git。脚本只操作专属环境、`vendor-sources/optimization`、`build/optimization`、`bin/optimization` 和 `licenses/optimization`，不导入 app、不连接业务数据库。当前原生构建目标为 macOS arm64；其他系统须在目标平台重新构建验证。

OR-Tools 固定 `9.15.6755`，CMake 固定 `3.31.6`，Ninja 固定 `1.11.1.4`；成功安装后保存完整 `requirements-optimization.lock.txt`。PackingSolver 固定官方提交 `4ba84e45ab4b7697d2fec2bb62bdca09dab56d29`，`PACKINGSOLVER_USE_HIGHS=ON`、CLP 和 Knitro 均 OFF。源码自身 CMake 固定其 fontanf 依赖提交、Boost 1.84.0、HiGHS 1.13.1 与 nlohmann/json 3.11.3。

主许可证分别为 Apache-2.0（OR-Tools）、MIT（PackingSolver 与 HiGHS）；Boost 为 Boost Software License 1.0。最终二进制、完整依赖版本及收集到的许可见 `licenses/optimization/manifest.json` 与 `python/`、`cpp/`。不要把整个环境概称单一 MIT，也不要启用未授权的商业后端。每次改变锁定版本须重建、核验依赖并重跑真实引擎测试。

```sh
KANPACE_TEST_REAL_ENGINES=1 python3 -m unittest discover -s tests -p test_optimization_engines.py -v
```

真实测试使用临时 SQLite Store 和独立测试板材，没有写入正式订单或启动/重启主服务。未设置开关时只运行轻量输入/证书测试并明确跳过真实引擎测试，不能把跳过算作引擎验收通过。

官方来源：[OR-Tools](https://github.com/google/or-tools)、[PackingSolver](https://github.com/fontanf/packingsolver)、[HiGHS](https://github.com/ERGO-Code/HiGHS)、[Boost](https://www.boost.org/users/license.html)。
