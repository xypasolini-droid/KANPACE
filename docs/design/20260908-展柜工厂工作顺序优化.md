# 展柜工厂工作顺序优化 · 2026-09-08

## 决策摘要
- 产品：KANPACE 展柜工厂端，与配置中台共用现有后端。
- 用户：50 岁以上老板、40 岁以上生产管理者、技术拆单员；电脑为主，手机查询。
- 首要任务：从真实订单看清当前阻碍，进入正确工序，完成一次明确操作。
- 可观察结果：五阶段主入口一击抵达；订单行有下一步；原图识别和待复核缺项直接可达；完成任务继续验收发货。
- 范围：已有 Web 的首页、导航、项目/拆单入口、Agent 拆单检查。使用原有数据契约、权限和发布门禁。

## 证据与问题
现场页面前3组导航同时展开、约32子入口；任务页面主按钮仍为导图；逾期提醒跳发货页而忽略当前阶段；任务完成和交付混为第4步；真实OCR和CAD核对在资料底部。

## 方向合约
- 主张：像厂长桌上的订单推进表，逐单看到卡点和下一步。
- 色彩：沿用 --paper #f5f6f8、--surface #ffffff、--ink #202935、--muted #657080、--blue #315ee8、--line #e6e9ee；风险用现有 --amber/--danger 且配文字。
- 字体：沿用系统中文字体，正文16px、说明14px、标题24/28px；数值用现有tabular-nums，禁止微小生产字段。
- 构图：侧栏5个编号阶段；主屏为待办数量→关键事项→订单推进表；操作助手采用当前订单上下文。
- 产品识别特征：五阶段编号和每单真实下一步，沿用批准KANPACE标志与真实效果图。
- 有理由的取舍：不把每项功能变成卡片；展开当前阶段，保留显式子入口；工程结果集中核对。
- 动效：仅按钮反馈，尊重 reduced-motion；不加装饰动画。
- 文案：接单建档→看图拆单→备料排产→车间执行→验收发货；“待复核”不能写成“已精准拆单”。
- 挑战后修订：优先级按真实交期紧迫程度和阻碍事实排序；无有效排程时不称预测延期。效果图只能作外观参考。AI未配置大模型时不伪称自由推理。

## 状态矩阵
| 入口/状态 | 反馈 | 行动与恢复 |
| --- | --- | --- |
| 今日待办/正常 | 真实计数、到期事实、当前步骤、下一步 | 筛选对应订单，进入阻碍位置 |
| 今日待办/无订单 | 准备首张真实订单 | 新建或Excel导入 |
| 物料接口加载/失败 | 正在核对/无法读取；不得当已齐套 | 重试，不清除已显示订单 |
| 拆单/仅效果图 | 外观参考、工程依据缺失 | 上传施工图或工程BOM |
| 拆单/原生CAD需转换 | 标记原件及所需工程导出 | 现有模型导入与来源核对入口 |
| 拆单/识别结果 | OCR原文或CAD实例、缺项及待复核 | 建构件、核对依据、确认工序 |
| 任务/暂停缺料 | 当前任务、原因、已完成量保留 | 现有暂停/交接/恢复动作 |
| 全部工序完成 | 待验收发货 | 质量验收和交付，不自动标发货 |
| 项目关闭 | 历史只读 | 查看记录，无派发入口 |
| Agent/缺项或来源变更 | 同一后端门禁的检查依据 | 指向具体资料/构件/流程，无隐式发布 |
| Agent/请求失败 | 错误与重试 | 不自动重复业务写入 |
| 权限不足/其他工厂 | 沿用后端权限、实例边界 | 不泄露对象或增加权限 |

## 实施约束与验收
沿用原生HTML/CSS/JS与Python，不替换技术栈、不新增云端连接；现有OR-Tools/PackingSolver/OCR/CAD核对仍从原接口调用。业务写入继续版本校验，导航与分析不改变生产数据。使用只读生产库散列基线、临时Store测试、桌面和窄屏真实浏览器、键盘与深链接验证；未实测硬件不得宣称真机通过。
