# Web 订单工作流设计与状态契约

日期：2026-10-04。依据用户批准的按操作流程组织方案。沿用现有 KANPACE 字标、系统字体、蓝色动作和线性图标，没有新增远端字体、图标或商业素材。

## 使用者与入口

主管、技术员和有整单查看权限的账号从订单进入。工人、质检账号继续进入自身任务范围，不能读取整单识别内容。默认首页为订单工作流，十个阶段按生产顺序展示；原有业务页面由阶段入口链接，用户能保留原先的深链接。

关键布局为当前订单与工程版本、十步阶段导航、当前阶段的资料/操作面板、该版本进度和阻断依据。桌面十步以两行五列排列；移动端在自身横向滚动容器内保留操作顺序。资料表使用语义 table、列标题、原件名称行标题和独立滚动区域；无页面横向溢出。

## 状态矩阵

| 状态 | 来源 | 界面行为 | 恢复路径 |
|---|---|---|---|
| 未建订单 | 当前场景无项目 | 新建订单空状态 | 原有订单创建表单 |
| 正在读取 | workflow/recognition GET 未完成 | 读取中提示 | 显示返回数据；切换订单使旧响应失效 |
| 没有原件 | 已登记来源为空 | 上传说明、识别按钮禁用 | 原上传接口 |
| 找不到文件 | 文件名过滤无匹配 | 独立空状态，输入焦点保留 | 修改关键词 |
| 模型未配置 | capability.available 不为 true | 明确待配置、模型选项禁用 | 服务器管理员部署实际 worker |
| 识别排队/运行 | 持久 job 状态 | 完成份数、后台轮询 | 页签可关闭；隐藏页面停止轮询 |
| 识别完成 | job 完成且有证据 | 已提取、逐条待复核 | 回原页与构件复核；不显示已审批 |
| 部分失败/中断 | 检查点与 worker 状态 | 明确失败文件与继续入口 | 同任务续跑保留已完成结果 |
| 来源过期 | 哈希或文件/项目版本变化 | 历史结果与失效说明 | 对当前资料重新识别 |
| 未知时长/待复核尺寸/缺料 | 实际业务门槛 | 待补齐与具体原因 | 对应工艺、构件、物料页面 |
| 归档订单 | 现有关单状态 | 保留资料与历史，禁用识别/上传 | 原重新打开订单操作 |
| 网络/权限错误 | HTTP 状态 | 可读错误与重新读取 | 登录或读取，不自动重放 POST |

## 交互与验收

原页定位使用真实 PDF 点坐标、左上原点及已校验页大小，显示框按百分比缩放；图像像素和 PDF 点不混用。所有文件名、文字和来源标识经过 HTML 转义。结果仅作为观察证据，后续采用使用原有审核、版本、库存和开工约束。

键盘可访问按钮、选择框、复选框与表格滚动容器，焦点明显；搜索刷新恢复输入焦点与光标。移动菜单为原生 disclosure，阶段深链接保留当前订单。reduce-motion 不要求动画。识别写请求只发一次，后台数据刷新不能使写入按钮永久卡住；登出/切换订单作废旧读取和写入 UI 回调。

验收使用合成订单，不使用客户资料。桌面 1440×1000、移动 390×844 检查导航、表格自身滚动、空状态、禁用状态、焦点、PDF 字框对齐。截图和测试结果见 `docs/verification/web-upgrade-20261004/`。
