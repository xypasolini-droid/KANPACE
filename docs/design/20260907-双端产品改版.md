# 双端产品改版

目标：中台配置一家工厂的流程并留下启用回执；工厂端让管理者看到订单下一步并直接进入已有操作。

受众：中台为实施人员；工厂端为不熟悉软件的老板、主管和工人。保留现有 KANPACE 品牌、原生 Python/JS 和真实业务接口。

方向：以现场交接单为布局依据，订单、待处理事项、当前工序及下一动作优先。中台采用左侧工厂名单、右侧步骤编辑与预览；工厂采用订单列表与四段状态。避免又造一页指标卡。

配色沿用白色纸面 #ffffff、页面底 #f5f6f8、文字 #202735、次要文字 #596579、主动作蓝 #345bf5、需处理琥珀 #9a610b。系统中文无衬线；正文与控件 16px，说明 14px，标题 24–30px。44px 最小点击区域，清晰键盘焦点。

主特征：同一份工厂流程配置在中台可预览串并行、任务卡和缺项，启用后在工厂端显示版本并能选择已发布模板生成真实工作包。工厂订单四阶段均有直接入口，状态依据真实记录，未知不自动填成已完成。

克制：效果图与加工依据分别标注；无真实整体模型时不生成推测模型；工厂页不出现开通其他客户或行业研究入口。动画仅加载与操作反馈。

方向挑战：四阶段会不会掩盖异常？保留暂停、待重审、缺料、待验收直接入口，阶段仅组织操作。中台是否只是另一张表单？预览必须纯计算、保存必须版本化、启用必须生成可用模板与回执。两个入口是否只是换标题？中台 API 需管理员并禁止子实例；子实例使用独立存储、固定场景、自己的账号。

状态矩阵：未登录→本端登录；中台未设账号→本地设置；无工厂→开通表单；无方案→参考模板；编辑→保存草稿；预览→显示依赖与缺项；过期→重新预览；启用→不可变版本及回执；断网→保留填写并允许同请求号重试；工厂空订单→导入首单；无工程源/无主模型/关闭订单→对应明确下一步。

验证：临时 Store 的权限、工厂归属、幂等、版本冲突、预览不写任务；现有导航/工程图/工作包回归；浏览器桌面、900px、390px、键盘、加载错误与账号隔离。实际客户订单、任务、图纸只读，不创建演示生产记录。
