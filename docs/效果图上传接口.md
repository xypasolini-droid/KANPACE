# 项目效果图与工程文件

项目效果图只描述外观，施工图、BOM 和实际模型保留各自的工程用途。上传效果图不会增加工程版本，不会创建或修改构件与任务，也不会成为任务发布的待转换阻塞项。

## 本地图片组件

本机已在项目 `.venv` 中安装 Pillow 12.3.0。将源码移到其他电脑后，首次使用图片上传可在项目目录运行：

```sh
python3 setup_media.py
```

安装完成后重新运行原启动文件。脚本将 `requirements-media.txt` 中的 Pillow 装入本项目 `.venv`，与 USB 串口组件共用环境。安装组件需要首次获取依赖；图片上传、校验和显示全部在本机完成，不调用在线服务。缺少组件时图片上传明确返回 503，其他已有功能仍可运行。

## 上传

`POST /api/import`

```json
{
  "project_id": "prj_…",
  "filename": "项目整体效果图.jpg",
  "purpose": "render",
  "content_base64": "…"
}
```

- `purpose` 缺省为 `drawing`，既有图纸导入保持原流程。
- `render` 支持 JPG / JPEG、PNG、WebP 静态图片。文件非空且不超过 20 MB，最多 3600 万像素、单边不超过 20000 像素。
- 先校验真实格式与扩展名一致，再完整解码。拒绝损坏图片、动画、SVG 和伪装后缀；不会用归档成功代替校验成功。
- 完成或发货项目返回 409，仍需重新打开项目才能上传。
- 同一项目、同一用途、同一 SHA-256 重复上传不新建记录。同名新内容只替换该用途的旧记录；效果图与工程文件互不覆盖。

成功结果保持既有 `document / parts / warnings / duplicate / existing_drafts` 结构，并附带 `render` 展示对象。效果图文档的关键字段为：

```json
{
  "purpose": "render",
  "status": "reference",
  "resolved": true,
  "part_count": 0,
  "image": {"width": 1920, "height": 1080, "mime_type": "image/jpeg"},
  "image_url": "/api/documents/doc_…/image"
}
```

效果图文档不记录工程 `revision`。`parts` 为空；前端不应将它计入待转换工程来源。

## 展示

`GET /api/projects/{project_id}/drawing-media` 继续返回 `parts`、`sources`，新增 `renders` 数组。顺序为本项目最新上传的有效效果图，然后是从订单资料建立的效果图关联。每项含 `id / title / kind / source_file / url / thumb_url`；上传图另含 `document_id / width / height`。

`GET /api/documents/{document_id}/image` 只读取已注册为效果图的上传文档，返回正确的图片 MIME，可直接用于 `<img>`。原文件下载仍使用已有 `/download` 接口。接口不接受任意文件路径，并拒绝越出上传目录的符号链接。已替换的旧图仍保留在历史文档中，项目完成发货后也可查看。

上传图片保留原始文件，`thumb_url` 当前与 `url` 相同；订单资料导出的缓存图片可使用各自缩略图。
