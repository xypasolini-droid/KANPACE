日期：2026-09-12。范围：既有工厂 Web 的六步顺序、按日任务、实体标签和货位、胸牌领还、ESP32-C3 1.6.0 固件与独立外观交互预览。

## 实现与参考

按用户路径图组织资料导入→任务排程→胸牌派工→现场执行→确认贴标→归还胸牌。用户新增参考图用于工件标签与货位标签的版式：黑白字段、唯一短码、二维码，大字货位号。沿用一个实体工件标识，跨工序确认分开记录。原有排程、工程放行、暂停、完成、设备收件与业务回执继续由原服务处理。

## 浏览器与真实服务验证

测试库位于工作目录内独立 `work/r32-qa-data`，不指向生产数据。合成验收订单名含“[隔离验收]”，两项工序 `qa_cut`、`qa_edge` 引用同一部件 `qa_part` 的两件实物。

1. 六步界面按工作日期读取上述两项计划；准备得到两个独立标签、四条工序上下文。
2. 新增 `01-007` 货位，并通过界面将第一件部件登记到该位置；刷新可见保存结果。
3. 领取 `QA-BADGE-01`，未完工时归还 API 拒绝。
4. 通过原执行 API 完成两项合成工序；在浏览器逐项确认四个工序/工件组合。第一道工序确认后，第二道仍待确认。
5. 确认全部完成后，归还页面解除阻塞；点击“已收到胸牌”后显示已归还。没有声称连接到实物工牌。
6. 胸牌外观预览完成开工→异常网格→缺料暂停→切换其他任务→完成→贴标弹窗。预览模型与真实业务记录分离。
7. 延迟前端模块加载时曾复现首次打开卡在加载状态；已修正为全部 deferred 模块就绪后启动。冷启动与刷新 labels / return 均保持日期与步骤；根任务在应用内浏览器再次确认刷新后直接打开贴标打印弹窗。
8. 320px 窄屏无横向溢出，胸牌主要动作按钮高 48px；390px 问题弹窗可用；Escape 关闭后焦点回到“遇到问题”。桌面检查了大图与侧键。

## 标签打印

- 使用应用内原生弹窗与 iframe 预览，不依赖额外弹出窗口；用户点击后才发起打印。
- 工件纸默认 80×50mm，可选 100×60mm；货位纸默认 80×30mm，可选 100×40mm。二维码静区保留四模块。
- Web 代理在隔离实例的实际预览中检查：两张工件标签无溢出，货位标签无溢出；生成的两页验收 PDF 约 80.09×50.12mm/页。独立 HTML 下载在 390px 窄屏成功。
- 超长字段在浏览器测试中触发可见错误并阻止打印/下载，避免悄悄截断编号或字段；未改数据库。

本机服务已启动，`/factory/index.html`、`/badge-studio/index.html`、健康检查和每日工作接口均返回成功。新 Web 代码使用真实库；测试写操作仅在 8775 隔离服务完成。
