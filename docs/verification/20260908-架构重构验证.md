# 2026-09-08 KANPACE 核心架构重构验证

## 范围和实施结果

在原有软件上重构入口、HTTP、应用服务、持久化、Agent 范围和工厂主页面传输层。实际结构见 [架构说明](../architecture/ARCHITECTURE.md)。原有生产规则、数据库格式、HTTP 地址、五阶段操作界面与工牌协议继续使用。

- `app.py` 从 2,023 行缩减为 47 行兼容入口；实现迁至 `kanpace` 包。
- Store 组合八个应用服务，服务复用用例连接；保留旧公开方法签名。
- SQLiteRepository 负责存储结构、连接和事务。BootstrapService 在锁内初始化默认设置并判断是否允许演示数据，异常时整体回滚。
- HTTP 工程来源绑定在成功提交后才返回成功，并在写锁内重新检查权限。
- AgentScope 由已认证服务端账号和当前实例构建；工作流事实包为明确字段投影。
- 主应用常规请求、执行、工牌、账号与助手接入可独立测试的 HTTP 客户端。

## 交付和能力边界

打包工具显式加入完整 `kanpace/`、前端 HTTP 核心和架构文档。包内保留第三方许可证、组件清单及原有 ESP32-C3 1.5.2 固件源码/二进制对应摘要。源码包的逐文件 SHA-256、ZIP CRC、独立临时数据库启动与双端 HTTP 结果记录在交付目录的 `源码包验证结果.json`，以该回执判断最终包是否通过。

本轮没有增加依赖、安装新模型、重新编译或刷写工牌。硬件相关自动测试采用现有模拟与协议回归，不能表述为实板重新验收。

这一轮完成核心边界的重建；根目录仍保留专业业务模块，主前端仍有全局状态和整页刷新。现有模型、排程和排料能力经适配器接入，本轮没有训练自有制造业模型，也没有证据宣称识图准确率或生产效率获得某个百分比提升。
