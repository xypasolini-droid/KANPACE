# KANPACE 真实工程引擎验收 · 2026-09-07

本次增加 PaddleOCR 本地扫描图识别与 OCCT 后端 STEP 实体检查。不是网格查看器的重复包装，也不是模拟识别数据。没有读取或修改正式订单，没有操作主服务、ESP32、网络凭据或客户云账户。

## 验证环境

- macOS arm64，物理内存 8 GB。
- 独立 `.venv-engineering`，Python 3.12.14；原 Web 环境未改。
- PaddleOCR 3.3.2、PaddlePaddle 3.2.2、PaddleX 3.3.13。
- cadquery-ocp 7.8.1.1.post1，实际加载 OCCT 7.8.1 动态库；VTK 9.3.1。
- PDF 栅格化使用 pypdfium2 4.30.0，图像使用 Pillow 11.3.0。
- 完整 67 包版本记录为 `requirements-engineering.lock.txt`。`uv pip check` 返回全部兼容。

本机使用官方 PP-OCRv5 **mobile** 模型，单 CPU 线程。server 模型最初虽然成功创建，但在当前 8 GB 内存负载下产生严重换页，不能作为本轮可用默认配置；该测试被终止并明确记录失败，没有作为通过结果。更换 mobile 后，真实 PDF 测试独立完成耗时 20.215 秒。耗时是本次合成样例运行结果，不是所有客户图纸的性能承诺。

| 模型 | 固定 revision | 参数文件字节数 | 官方模型卡许可 |
|---|---|---:|---|
| PP-OCRv5_mobile_det | `0d63e78e2b680928f6b1747d76a08db6e645efb7` | 4692937 | Apache-2.0 |
| PP-OCRv5_mobile_rec | `682f20538d8c086cb2128e5cfac775e6c4904e85` | 16458665 | Apache-2.0 |

模型来源、配置文件和权重 SHA256 见 `models/engineering/manifest.json`；执行前校验摘要。首次下载仅取得公开模型，客户图纸推理禁止联网。

## 实际测试结果

运行命令：

```sh
.venv-engineering/bin/python -m unittest tests.test_engineering_engines -v
```

**11 项独立测试全部通过，52.015 秒，无 skip。**

| 测试 | 实际输入和结果 |
|---|---|
| PDF 文字识别 | PIL 生成中文扫描图并制成两页 raster-only PDF，无文本层；只选择第 2 页。真实 PaddleOCR 识别出“柜体”、600、450，得到至少四个文字框、0—1 分数，所有段落 page=2，保留页图。 |
| WebP 原页识别 | 同一合成施工图保存为 WebP，真实推理；内部 page=1，原施工图 source_page=14，source_id 保留，段落和预览文件都能对应来源。 |
| 毫米 STEP | OCCT 真正构造并写出一个 10×20×30 mm 零件的两个装配实例，再由独立 worker 读回；1 个定义、2 个实例，总面积 4400 mm²、总体积 12000 mm³，两个实例外包框起点分别 x=0 与 x=100。 |
| 英寸 STEP | 源 STEP 声明 INCH，实体坐标为 10×20×30；两实例体积 12000 in³ 被读入为 196644768 mm³，每件外包尺寸为 254×508×762 mm。 |
| 非法 STEP | 非 STEP 字节输入返回 `invalid_step`，没有伪造面积体积；公共错误不泄露工厂路径。 |
| 跨工厂源 | 工厂 A 提交工厂 B 文件，被拒绝。 |
| 符号链接 | 本厂内符号链接也被拒绝，不能借链接绕过源约束。 |
| 跨工厂 job | 不存在于本厂的 job 与目录穿越请求被拒绝。 |
| 原生 SolidWorks | `.sldprt` 返回需要 SolidWorks 导出桥接的明确提示。 |
| 页码校验 | 重复页码被拒绝。 |
| 操作系统隔离 | 在真实 `sandbox-exec` 子进程内尝试读取/覆写另一工厂文件及建立网络连接，均收到权限拒绝；原文件不变。 |

引擎状态探针另经过真实运行：OCCT 创建 1 mm 立方体、Paddle 执行 CPU tensor 求和，并检查 OCR 模块及本地模型文件。返回 CAD/OCR `ready=true`，耗时 6.82 秒。状态探针不声称完成全文识别；全文处理由上表的真实 OCR 测试证明。

提供给根任务 UI 验收的 `qa-native.step` 也由真实 OCCT 生成，只有该临时工厂的 uploads 文件被写入，注册文档及 HTTP/浏览器验收由根任务负责。本报告不把单元测试当作整条 Web 交互链的验收。

## 能力与结果边界

- OCR 结果保存原文、分数、页码和图上坐标，默认等待技术员复核；不把模型分数叫作工程正确率，不自动把 OCR 数字当加工尺寸。
- CAD 面积、体积来自源 B-rep，支持装配实例与单位核对；世界坐标轴对齐外包框不是下料尺寸。
- 不推断源文件缺失的材料、密度或重量，不恢复 SolidWorks 参数历史，不生成制造工艺或工程 BOM；本轮未解析 PMI。
- 本次几何与 OCR 原生验收使用合成资料。真实客户全部订单的识别准确率、复杂装配覆盖率仍需逐类样本回归。
- 每工厂输入、结果、预览和日志单独存放；只读公开模型共享。macOS 原生进程禁止网络，并限制受保护用户/工厂目录的访问。这里不是不同操作系统管理员之间的隔离。

## 许可留档

`licenses/engineering` 留存 67 个 Python 包的许可/版权证据、固定模型卡和模型 manifest，以及 OCCT LGPL 与例外。部分大 wheel 下载使用清华镜像提速，安装前逐个核对官方 PyPI 公布的 SHA256，原始 URL、文件名和校验记录一同归档。

实际 OCP 包装器为 Apache-2.0，内嵌 OCCT、FreeImage、LibRaw 和其他原生库保留各自许可。FreeImage 3.18.0 与 LibRaw 0.21.3 的原生版本 API 已独立核验，许可正文已补归档；完整分析见 `work/engineering-license-audit/embedded-freeimage-libraw-audit.md`。

本轮完成的是本机真实接入和可复现安装，不是已经完成全部原生库分发义务的商业二进制发行包。对外发行仍需落实适用版权/NOTICE、对应源码与构建材料、库替换或重新链接及源码获取安排。不存在把包装器 Apache 标识延伸到整个 wheel 的结论。
