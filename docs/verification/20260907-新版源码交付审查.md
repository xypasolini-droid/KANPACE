## 新引擎的复现条件

`tools/setup_intelligence.py` 是工程、优化、Agent 三组共五项引擎的统一入口：

```bash
python3 tools/setup_intelligence.py --python 3.12
python3 tools/setup_intelligence.py --check
```

第一条安装工程环境还需 `uv`，优化构建还需 Git 和本机 C++ 工具链；首次安装要联网下载依赖/模型/源码。第二条会实际探测已安装引擎，其中 PackingSolver 包含小型合成求解，不是纯文件存在性检查。本审查未执行这两条命令。

## PackingSolver 源码归档注意事项

当前主源码固定提交 `4ba84e45ab4b7697d2fec2bb62bdca09dab56d29`，依赖包括七个固定提交的 fontanf 工程、HiGHS 1.13.1、Boost 1.84.0。以 `licenses/optimization/fontanf-sources.json`、`licenses/optimization/manifest.json`、上游 `extern/CMakeLists.txt` 保存完整映射。Boost 原档 SHA-256：`2e64e5d79a738d0fa6fb546c6e5c2bd28f88d268a2a080546f74e5ff98f29d0e`。

**不能简单将去掉 `.git` 的 PackingSolver 源树原位塞入源码包，然后承诺安装器离线可用。** `setup_optimization.py` 以 `.git` 是否存在判断是否初始化仓库；随后 fetch/checkout 固定提交，预置的未跟踪同名文件可能阻断 checkout。可选做法：

1. 通用源码不带 `vendor-sources/`，按现有安装入口联网取得固定源；另外保留独立源码归档供审计。
2. 若要求离线重建，则提供明确的本地 Git bundle 克隆/源码恢复步骤或专用 CMake 构建入口，并核验所有依赖摘要；不要把上游源码归档误当成当前安装器已经实现离线恢复。

不要复制 `archives/boost.headers.*` 等下载过程文件、CMake 缓存、原机编译产物和 Git 配置。归档应按组件记录提交、来源、文件数、SHA-256，并保留适用许可证。
