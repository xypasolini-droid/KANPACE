# 工程状态探针修正 · 2026-09-07

正式 Web 首次检查约 40 秒后返回 `versions={}`，而原生 OCR/CAD 测试已经通过。旧实现会丢弃超时输出与 stderr，并将空结果缓存 60 秒；顺序加载 Paddle 超时也会把已成功的 CAD 一并抹去。

原始失败的 stderr 已被旧实现丢弃，不能将其根因断言为 TCC 或某个库不兼容。在正式 `data/engineering-jobs/_probe`、相同文档化 launchd PATH 与相同 sandbox 配置下，独立原生探针实际退出 0，双引擎均成功，首次用时 26.912 秒。当前证据更符合冷加载/内存换页引起的瞬时超时；真正 launchd 首次探针仍以主任务重启后的私有日志为准。

修正内容：

- CAD 真正创建立方体后立即刷新阶段结果；Paddle 后续超时不再抹去 CAD 成功证据。
- 每次原生检查记录退出码、耗时、stdout 与 stderr 到当前工厂 `_probe/probe-log.json`。文件权限 0600；HTTP 只返回检查状态和公共提示，不返回日志正文。
- 只有双引擎原生检查全部成功才保存健康记录。成功记录绑定解释器、实际原生库、依赖元数据、模型文件/manifest、执行环境与引擎程序的指纹；变化即失效，最长有效 24 小时。该记录不来自仅查看 dist-info 的推断。
- 成功状态进程内缓存 10 分钟，失败状态仅缓存 5 秒；并发状态请求不会同时启动多个昂贵探针。
- 超时、检查失败、另一个检查正在运行被明确区分；损坏的健康记录会触发重新检查。

验证结果：

- 修正后真实原生探针在正式探针目录完成，**5.413 秒**，CAD/OCR 均为 true。
- 清空内存缓存后复用成功记录 **0.005 秒**；另开独立 Python 进程实际复用记录 **0.021 秒**，仍为双引擎 true。
- `python3 -m unittest tests.test_engineering_status -v`：**5/5 通过，0.016 秒**。这些是明确的故障注入回归，分别验证超时保留 CAD 与日志保密、持久成功记录/运行库变更失效、失败短缓存、损坏记录恢复、并发限制；不将它们计作全文 OCR 原生准确率测试。

原生 OCR/STEP 验收仍见 `20260907-真实工程引擎验收.md`。正式 HTTP 最终记录由主任务在服务更新后写入 `intelligence-live-status.json`。
