# KANPACE（交付引力）产品说明

**版本：2026-09-23 整理版｜首个场景：木作、五金、玻璃、灯光综合展示柜**

> 让正确任务到现场，让现场问题找到能解决的人，让处理结果得到确认。

## 1. 一页看懂产品

KANPACE 是连接工厂已有资料与现场作业的智能协同平台。首个落地场景是非标展柜工厂：订单资料分散在效果图、施工图、工程图、模型和 Excel 排程表中，技术员拆单后还要靠表格、群消息和口头交接把工作送给木工、五金、玻璃、电工及装配人员。图纸改版、缺料、插单或质量异常发生时，管理者需要知道**哪个任务受影响、谁负责处理、现场是否收到并确认**。

产品由两个 Web 入口和一个现场终端组成：配置中台复制行业参考流程并核定本厂规则；工厂 Web 管理项目、工程依据、任务排程、备料、派工、异常、验收和交付；智能胸牌让工人看清当前任务与关键图纸，并用少量操作回传现场状态。KANPACE 不替代客户的 ERP／MES 主数据；目前优先与 Excel 文件衔接，正式系统 API 集成按客户现有系统逐项实施。

| 使用者 | 最需要看到或完成的事 |
| --- | --- |
| 老板／厂长 | 哪些订单能按期交付、卡在哪一环、异常有没有负责人和处理结果 |
| 生产管理者 | 工序先后、人员与胸牌绑定、缺料及插单后的重新排程 |
| 工程技术员 | 根据原图和模型核对构件、数量、材料、加工尺寸与工程版本 |
| 工人／质检 | 当前做什么、看哪张图、完成标准是什么；遇阻能立即反馈 |
| IT／实施伙伴 | 本厂数据边界、人员权限、设备身份、备份与系统接口 |

## 2. 软件端：接单到发货

**中台开厂（一次） → 接单建项目 → 看图拆单与人工复核 → 生成并发布任务 → 备料排程 → 按项目派工 → 现场异常与完工 → 贴标质检 → 发货留档。** [完整软件流程图](KANPACE-软件端与硬件端流程图.md)。

1. **中台先配置本厂。** 从现有 19 个行业参考目录选择生产类型，复制岗位、工序、前后关系和验收项，再由本厂负责人核定启用。模板提供起点，不把其他工厂的订单、价格或图纸带进本厂。
2. **资料按用途使用。** 效果图用来看整体外观；施工图和工程图用来核构件、尺寸与做法；有 STEP 模型时，读取装配实例和几何作辅助。Excel 排程表与人员分工继续作为当前工厂的习惯入口。原文件、版本和来源留在项目中。
3. **先提候选，再由技术员定单。** 本地 OCR 提取图纸文字与原页位置，STEP 引擎提取实例、装配路径及几何参考；同项目当前文件之间可显示疑似对应和冲突。数量、材料、加工长宽厚及工艺由技术员对照原图确认，再审核为生产依据。效果图、模型外包尺寸或 OCR 数字都不能直接变成下料尺寸。
4. **发布后才排产派工。** 已审核构件生成木作、五金、玻璃、灯光等工种任务；当前工程版本通过发布检查后，管理者核对物料需求与库存，形成采购草稿，按 Excel 排程表调整工序先后、日期和人员。插单在排程中改顺序，不能抹去已执行记录。
5. **整项目送到人。** 工人与胸牌绑定，系统按项目建立派工队列；每项任务带所需图纸。设备收件回执只说明任务到达，开工和完工由另外的业务事件记录。
6. **异常形成闭环。** 工人遇到缺料、质量、设备或插单问题可暂停并留下原因；管理者在 Web 处理后恢复原任务或改派。工序完工、逐件二维码贴标、质量验收和发货分别确认。完成／发货项目保留历史，不再出现在待派工列表。

## 3. 硬件端：工人的当前任务

**领取胸牌 → 接收当前任务 → 看大字任务和施工图 → 确认开工 → 进行中／遇阻暂停 → 完工 → 核对实物标签 → 下一项或归还。** [完整硬件流程图](KANPACE-软件端与硬件端流程图.md)。

胸牌首页突出工种、工人、部件、工序和数量；工人可打开施工图与效果图的 JPEG 图册、放大或移动，并查看操作要点。任务收到后有独立收件 ACK；开工、暂停、恢复、完工与贴标操作先保存为待同步事件，收到业务 ACK 后才更新生产状态。暂停原因包括缺料、质量、设备、插单和其他。标签由 Web 准备；胸牌显示短码，工人对照实物人工贴标确认。胸牌只缓存最近一项任务，不宣称有整日离线队列。

当前固件代码支持 USB 和已配置的 2.4 GHz Wi-Fi 收任务，**图片传输和业务报工目前使用 USB**。仓库内 1.6.1 开发镜像已构建并通过主机测试，但本整理版未重新烧录或完成多胸牌真实厂区验收。概念外观里的摄像头扫码、拍照录像、AI 图像质检、旋钮和橙色侧键不属于现阶段已验证功能。完整工程图和复杂反馈更适合 Web／工位屏，胸牌保留当前任务与最少操作。

## 4. 两端如何配合

| 状态 | Web 负责 | 胸牌负责 |
| --- | --- | --- |
| 依据与版本 | 保管订单原件、工程版本、任务及图册 | 仅接收当前工作需要的任务和图片 |
| 送达 | 绑定人员、设备并下发；记录设备收件回执 | 校验并保存任务，回传“已收到” |
| 执行 | 校验前序、物料、权限和版本；记录业务事件 | 工人触屏确认开工、暂停、恢复、完工 |
| 异常 | 指派负责人、处理缺料／质量／插单并调序 | 把原因和当前任务上下文带回 Web |
| 完成 | 逐件标签、质检、货位、发货、归还分别记录 | 核短码、贴实物；收到允许归还的最新回执后提示 |

各工厂资料单独存放、按本厂角色授权，行业模板不共享客户订单内容。当前本地运行和数据库隔离是可演示基础；客户环境中的网络分区、加密传输、设备吊销、备份恢复及外部 ERP／MES 回写须按部署方案验证，不能因为“本地部署”就假定已经达标。

## 5. 当前能演示什么，尚需验证什么

| 能力 | 当前状态 | 下一项真实验证 |
| --- | --- | --- |
| 双 Web 入口与行业模板 | 工厂端、中台已可运行；19 行业参考可复制为本厂配置 | 用目标工厂真实工序核定模板 |
| 图纸与模型拆解 | PDF／图片 OCR、STEP 几何与装配候选、原图定位、冲突提示；人工审核后才能发布 | 三单含人工金标准 BOM 的盲测，记录召回、错误和复核时间 |
| 排程、物料、派工 | Excel 排程、任务依赖、库存缺口与采购草稿、整项目派工队列 | 一个真实班次的交期、缺料和插单对照测试 |
| 胸牌联动 | USB 可承载图片与业务报工；Wi-Fi 可收任务；固件代码保留待同步事件 | 1.6.1 实板烧录，多胸牌、断网、续航和厂区覆盖测试 |
| 摄像头质检／通用系统 API | 仍为规划或待客户系统确认 | 明确硬件方案及目标 ERP／MES 版本、接口与数据授权 |

目前没有足以对外宣称的真实客户拆单准确率、节省工时百分比或单厂投资回报率。试点前记录人工基线，试点中统计**图纸版本错误、任务触达时间、异常关闭时间、工程师修改候选数、工人实际使用率和交付延误原因**；由客户确认统计口径，再决定扩展与报价。
