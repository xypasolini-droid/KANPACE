# 泉州工厂业务链与 KANPACE 产品规划

调研日期：2026-09-07。面向 KANPACE 产品决策、工厂老板访谈及首单实施。

## 直接结论

KANPACE 应先做好“把已确认的订单与技术资料，变成工人拿到就知道做什么的图文任务，并追踪跨工种交接”。第一批优先验证展柜既有业务，以及安溪藤铁木作、南安石材工程、泉州专用机械这三种邻近场景。这个排序依据现有产品能力的复用程度，尚未经过客户付费意愿验证。

本次沿用户提供的《泉州产业调研2607_V2.html》研究九大产业领域，进一步区分为 19 类工厂业务场景。官方研究也采用县域细分产业链口径：泉州对 13 个县域梳理了 50 条重点产业链。因此，产业集群名称适合市场地图，配置软件还要细到工厂实际承担的制造环节。[泉州市科技局，2024-11-05](https://kj.quanzhou.gov.cn/xxgk/kjxw/202411/t20241105_3101227.htm)

本报告与配套图谱是桌面研究和产品建模建议。没有访问工厂现场，没有得到完整的现行 SOP、真实工时、客户付费结果，也没有把这些行业模板自动安装到任何客户空间。用户原文件的 GDP、产值、份额、企业数未逐项核验；不同年份、规上/全口径、产业链/工业产值不用于相加或计算本产品市场规模。

## 一、先按实际工作对象组织软件

| 组织方式 | 代表业务 | 系统必须认清什么 | 适合优先提供什么 |
|---|---|---|---|
| 工程与装配 | 展柜、藤铁家居、机械、石材工程 | 项目、柜/部套/板件、图号、版本、安装位置 | 图文交底、按对象齐套、外协交接、分批交付 |
| 款式与工序流水 | 成鞋、成衣、纸盒印刷 | 款色码、扎包、签样版次、工序批 | 正确版本到工位、配套缺口、批量转序、返修 |
| 批次加工与装配 | 染整、陶瓷、食品、茶、香、卫浴 | 配方/模具、投入批、产出批、窑次/缸号、合格数量 | 批次流转、准备和等待、质量放行、数量交接 |
| 连续或专用制造 | 建陶、原纸、卫生用品、石化、半导体 | 线体/设备、时段、换型、卷/批、原系统的过程状态 | 先接异常、维修、换型、交班及已有系统状态 |

这些是可组合的业务模型。一个智能卫浴厂可能同时有陶瓷批次、采购模块和整机装配；不能强迫全厂只选一种对象。半导体前道与电子装配分别建模，石化生产与设备检维修也分别建模。19 类详细路线、来源、输入资料、卡点、建议指标及硬件入口见配套图谱和 JSON 数据。

## 二、先替代一个付得起钱的人工环节

现有流程常见的一段是：技术员找图、裁图、抄清单 → 按工种重新做表 → 发群或打印 → 工人问位置、做法和版本 → 主管追进度并补 Excel。

建议首个交付闭环：接收已确认资料 → 对齐对象/编号/版本 → 生成分工草稿与缺项 → 技术员确认 → 每个岗位收到一张图文任务卡 → 暂停/换单/交接/验收 → 写回原表。

每张任务卡只需要：项目和对象、当前要做的动作、相关局部图、明确数量与单位、关键要求、预计完成/交接对象，以及开始、暂停、报问题、完成数量等当前可用操作。整体效果图作为可点开的定位参照。图纸缺制造信息时，形成“深化确认”待办，不能猜出尺寸后发生产任务。

机械行业已有公开参照：铁拓机械 2025 ESG 报告披露了设计资料按工序、班组分发到车间，以及图纸问题回流设计的做法。大型厂可能已具备 PLM，KANPACE 应接其发布结果，再补现场交接。[铁拓机械报告，第19–20页，2026-04-14披露路径](https://static.cninfo.com.cn/finalpage/2026-04-14/1225102146.PDF)

石材行业亦已有扫描、数字排版和生产管理系统，不能把“能看三维”当独有能力。优先补加工单到板件、包装箱与安装位置之间的交接缺口。[泉州市工信局，2021-05-26](https://gxj.quanzhou.gov.cn/zwgk/gzdt/202105/t20210526_2563618.htm)

电子客户也不能假设没有系统。科立讯于 2025-06-20 公布 IMS-WMES 二期启动；这证明有既有系统的场景存在，但不证明对外 API 开放或项目已验收。[科立讯官方公告](https://www.kirisun.com/kirisun-launches-phase-II-of-IMS-WMES-project)

## 三、用什么图，怎样拆更准更快

| 资料 | 正确用途 | KANPACE 下一步 |
|---|---|---|
| 客户效果图 / 3ds Max 场景 | 理解外观、空间和客户认可的样子 | 留作整体参照；设计端导出真实 GLB 才可旋转查看 |
| 已发布施工图 / 深化图 / 零件加工图 | 识别对象、材料、数量、尺寸、孔槽和验收要求 | 原图定位、OCR 辅助、字段核对、缺项追问 |
| SolidWorks 原生装配、零件、工程图和 BOM | 工程设计主档及正式制造信息 | 收齐引用文件、配置与版本；设计端导出发布 BOM、图纸和 STEP |
| STEP | 核对实体几何、结构和实例 | 辅助查错；不直接把包围尺寸当下料尺寸 |
| GLB / OBJ / STL | 浏览已导出外观或几何网格 | 可旋转、选择；不凭节点数确定订单数量 |
| 服装纸样、印刷刀模、PCB 资料、配方工艺卡 | 各行业的专用技术输入 | 按行业接入，不能统一改成 SolidWorks 图纸 |

网页使用派生模型是合理方式，关键是它必须由真实设计导出，并能回到原件版本。3ds Max 2026 官方支持 GLB 导出，但存在层级展平及材质等限制；这不是完整原生场景编辑。[Autodesk GLB 导出说明](https://help.autodesk.com/cloudhelp/2026/CHS/3DSMax-Interoperability/files/GUID-5B4C8EC2-2230-4F9F-B3C6-48D9E347E37D.htm) SolidWorks 装配应收齐引用文件，可用 Pack and Go 组织原件；只收一个 SLDASM 不能证明依赖齐全。[SOLIDWORKS Pack and Go](https://help.solidworks.com/2024/english/SolidWorks/sldworks/c_pack_and_go.htm)

准确和速度同时改进的顺序：优先复用已有加工单/BOM；按图号和版本确定对应对象；只对未结构化区域做 OCR；让人只核对冲突、缺失和关键制造字段；生成任务前检查来源、单位、数量和制造要求；任务引用固定发布版，变更只影响相关对象。这比对每张效果图重新猜模型更接近真实节省。

## 四、中台最先补的六个能力

1. **对象与路线匹配。** 同单木件、铁件、玻璃分别走路线；机械的机架和电柜也不同。目前企业工作包存在“每对象复制全部节点”的限制，需要替换成按对象类型选择路线。
2. **跨对象齐套。** 以柜号、设备部套、安装区域或款色码汇合。不能因一个柜缺玻璃，就挡住所有其他柜；也不能只看工种完成百分比。
3. **批次拆合及数量。** 多卷入缸、多批拼茶、一批分装、母卷分切都需要投入—处理—产出关系。合格、待检、返工、报废分开；单位与换算必须明确。
4. **人、设备、工艺等待分开计时。** 工人暂停换单可释放人员；窑炉烧成、涂层固化、茶焙火和晾香不会因此暂停。不把自然等待全部计为人工工时。
5. **资料角色和来源链。** 原生主档、整体效果、加工依据、派生模型、批准样分开，绑定来源与版本。项目主模型由人指定，不能用最后上传的零件冒充整体。
6. **可预览、可安装的工厂方案。** 行业通用包 + 本厂对象/工种/资源/字段映射 + 一单预演 + 主管确认 + 独立工厂安装回执。通用模板没有客户图纸、配方、价格或实际产能。

目前已有独立本地工厂实例、流程模板版本、工作包复核、任务执行、Excel预览导入及排程等基础；还没有完整的“上传资料就配置整厂”闭环。现有本地隔离也不等于云端多租户已验收。完整审计见《20260907-工厂配置中台审计.md》。

## 五、排产时间要怎样估，才不误导老板

单节点拆开记录准备/换型时间、人工投入、设备占用、工艺等待、外协运输和质检等待。人工时长、机器时间和交期时间分别展示。

首单先取本厂工艺员估计范围并注明依据；随后采集开始、暂停、恢复、合格产出与等待原因，用同产品族、数量、工位的可比实绩校准。没有实绩或工艺卡时显示“待估时”，不从企业规模或模型体积凭空给出分钟数。

没有资源冲突时，串行段累加、并行段由最晚满足条件的分支决定下步；实际还要检查共享人员/设备、批容量、齐套、检验、日历和外协到货。窑炉、染缸、连续纸机需要自己的容量模型。插单先看受影响订单与在制状态，不能因为优先级高就打断不可中断的工艺。

## 六、第一次见老板，收六包资料

| 要收的资料 | 用来回答什么 | 首次不必提供什么 |
|---|---|---|
| 一张代表性订单和原 Excel | 产品、数量、交期、客户编号 | 全年所有订单 |
| 这一单批准技术资料 | 图纸/样品/配方谁说了算，版本怎样区分 | 无关项目资产 |
| 实际流程与排程表 | 哪些自己做、哪些外协、哪里汇合 | 重新为软件画一套理想流程 |
| 班组、工位、设备和工作时间 | 谁会做、哪里做、什么资源最紧 | 初期复杂人事档案 |
| 当前库存/缺料与供应交接记录 | 到货怎样转为可用，外协怎样回厂 | 全套财务总账 |
| 一单完工/质检记录和一次异常 | 怎样算合格、怎样暂停换单、怎样验收收益 | 没有记录时猜准确工时 |

生成顺序：识别本厂职责 → 对应字段与对象 → 生成可核对路线、任务卡和缺项 → 老板/工艺负责人确认 → 安装本厂方案 → 用一单比对原表 → 正式启用。客户只看自己的资料和结果；本厂修改留在本厂，共用库仅沉淀经过授权的一般流程定义。

## 七、商业价值与试点顺序

优先顺序是产品判断，不是实测市场排名：

- 第一批：现有展柜样板 + 安溪藤铁木作 + 南安工程石材 + 专用机械小装配。共性是资料复杂、多工种、外协与齐套，最接近已有能力。
- 第二批：选一个成鞋/成衣款色码样板、一个纸盒版次样板，或卫浴配套/德化人工工序样板。每次验证一种新对象，避免同时铺开。
- 后续：食品茶、染整、香等补好批次和质量放行；建陶纸机等对接连续产线；石化、半导体先做外围检维修协同，核心控制与专用MES单独评估。

当地数字化试点曾明确聚焦休闲体育用品、食品加工、工程机械与纺织专用设备，可作为访谈与生态合作的线索；本报告不据旧申报通知承诺当前补贴资格或金额。[泉州市工信局，2025-04-08](https://gxj.quanzhou.gov.cn/zwgk/tzgg/202504/t20250408_3156490.htm)

建议每个样板先记录旧流程基线，再做同类订单对照：交底包准备时间；工人找图/问图次数；错版返工；缺件等待；一次合格产出；按承诺日期交付数量。追踪中位数和长尾，不把一个最快订单当平均值。

月度可核验收益可按“节省交底/追单人工 + 减少返工直接成本 + 减少有记录的加班/加急损失 − 新增运行和实施成本”核算。同一损失不重复计入，节省工时不自动等于现金节省。图谱列出的指标均为建议采集项，没有填虚构改善百分比。

真正可积累的壁垒是：来源到对象的可靠对应、经工艺验证的路线和例外、对象/批次交接、可解释的时间预测、无需工人反复填表的回执。开源内核提供基础能力，企业图纸和配方不能为了积累模型而跨客户混用。

## 八、页面与硬件收敛方向

日常入口建议围绕四件事组织：今天要办、项目与资料、排产与派工、经营情况。各组展开直接看到常用小标题，保留快速抵达；工牌连接和工厂配置作为固定辅助入口。Agent 接受“找出这单缺件”“安排已齐套的柜子”等动作，先定位对象、调用实际能力，必要时给差异预览。不能只靠聊天入口把常用功能藏得更深。

硬件共用一张当前任务卡，根据岗位换内容：木工看板件局部图，装配看部套，检验看标准样与判定，搬运看批次和位置。连续产线优先固定工位屏或自动计数；不能把“每人一块小屏”当成所有行业的答案。

## 九、本轮实际修改与未完成项

已把当前模型查看入口统一为“工程模型”，增加折叠的SolidWorks/3ds Max资料准备说明；旧推演页面改名“清单尺寸示意”，直接说明没有读取原设计模型；修正能力说明中对已存在排程/矩形套料的过时描述。本轮不改变导入器支持格式，也没有让MAX或原生SolidWorks变得可以直接解析。

项目主模型的显式指定、原件和派生文件关系、按对象路线/跨对象汇合、批次拆合、完整工厂方案安装仍是待实现项。可切换行业图谱是调研成果，不是已启用的19套工厂配置。既有生产数据不因这次调研或文案修正发生变更。
