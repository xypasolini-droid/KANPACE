# 展柜工厂五步工作流 · 2026-09-08

## 使用顺序

从工厂端首页“今日待办”开始，每张订单给出当前步骤、卡点和下一步。

| 顺序 | 人要做的事 | 软件提供的帮助 |
| --- | --- | --- |
| 1 接单建档 | 登记客户、交期，导入订单表和资料 | 保留原有 Excel 文件互联与订单档案 |
| 2 看图拆单 | 看整体效果，核对施工图/工程 BOM，确认构件与工序 | 原图识别、模型核对、缺项检查、来源与版本检查 |
| 3 备料排产 | 核对物料、开工条件、工序前后关系与人员能力 | 物料缺口、开工检查、既有排程分析与优化入口 |
| 4 车间执行 | 分配负责人、派发工牌、报工、暂停与恢复 | 图文任务、现场异常、工牌任务与回执 |
| 5 验收发货 | 验收、登记分批交付、确认整单发货 | 已完成待发货清单、检验记录与交付记录 |

五个阶段的标题可直接点击；旁边箭头展开本阶段子功能。当前阶段默认展开。经营数据放入“经营管理”，配置工具放入“工厂设置”。原有功能入口仍保留。工厂模块配置和权限继续约束可见入口。

## 一单一条推进路线

首页按合同交期紧迫程度、较早交期及当前阻碍排序，一单只给出一条优先行动。它是可解释的处理顺序，不是生产排程算法的计算结果，也不把历史交期直接说成预测延期。无效日期和未知日期不会被算成到期。

没有发布当前工程版本，继续核对拆单；已发布但有缺料或未满足的开工条件，去处理准备事项；已有报工进入车间执行，但已知缺料、异常和暂停继续显示。全部工序报完工后，先核对验收。标记“已完成·待发货”后停止生产派工，仍留在待发货；确认“已发货”后退出日常待办。

## 图纸与算法的分工

- 客户确认的效果图用于了解最终外观，不能提供未标注的制造尺寸。
- 施工图、CAD工程文件、结构化BOM和本厂工艺依据用于拆解生产对象。保持原文件、页码/行号/构件对应关系和工程版本。
- 原有 PaddleOCR 入口移到拆单页顶部。识别输出要在原图旁复核；OCR置信度不能当整单加工正确率。
- 原有 STEP/STP 模型核对与 SolidWorks 导出桥接继续使用。原生 SLDPRT/SLDASM/MAX 不能靠修改扩展名变成有效模型；需要相应软件导出可用工程文件。效果图也不会被自动猜成制造3D模型。
- 原有 OR-Tools 排程、PackingSolver 排料、LangGraph 多步骤工作流保留。这次没有替换或重新验收这些原生计算引擎。

## 工作助手

从当前订单打开助手时自动带入当前订单；从今日待办、订单总览等页面打开时默认查询整个工厂。可输入“检查当前订单的拆单依据”“检查这单的漏项”“下一步做什么”。输入建议只预填，不自动发出修改。

新增拆单检查复用正式发布的关键后端校验，核对构件是否为生产BOM、尺寸和材料等必填项、复核状态、工艺依据和工程版本。另检查来源文件一致性、过期绑定和重复文件；这些更严格的来源检查不会被谎称为全部已经成为发布API的强制门禁。原件检查存在本机读取预算，未核验的文件保留未核验状态。

结果显示具体缺项、来源与下一步入口；本次新增动作只导航，不自动批准构件、发布任务或改变排产。现有写操作仍有预览、确认、权限与版本校验。

当前实例未配置通用推理大模型。此次上线的是本地证据检查与工具工作流，不能描述成任意自然语言都能自动理解图纸、完成生产拆单。模型接入后的价值仍应由真实项目的漏项率、复核时间、变更返工、交期偏差衡量，不能用演示精度替代。

## 四个角色共同取舍

| 角色 | 这次决策 |
| --- | --- |
| 产品经理 | 用工作阶段组织页面；同一订单使用统一的当前状态和下一步 |
| 展柜工厂老板 | 先看到哪单要推进、哪里缺料、哪里暂停、哪单待交付 |
| 营销负责人 | 用一张真实订单讲清“资料进来—拆单确认—生产协同—验收交付”，价值用可记录的时间和错误改善衡量 |
| Agent研发 | 将原始依据、结构化数据、确定性校验和受控工具操作连起来；缺资料先指出缺项 |
