# KANPACE 真实自动拆图：来源、算法、审核和验收

> 2026-09-23。这里的“自动拆图”指**自动产生有来源依据的待审核构件和工序建议**，不是从一张效果图直接生成可下料清单。未经工程确认的数据不得发布生产任务。

## 先确定要替代哪一步

展柜工厂已有设计师效果图、施工图、局部工程图、可能存在的 SolidWorks 装配或 3ds Max 场景。最耗时的是技术员逐图找到柜组、构件、数量、尺寸、材料和做法，再抄进 BOM 和工单。KANPACE 首先替代**寻找、归集、比对和抄写候选信息**；技术员仍确认影响下料、采购、装配和质量的字段。确认后的 BOM 继续进入现有的备料、排程和派工流程。

输入的优先级随问题而不同：

| 要回答的问题 | 优先依据 | 不可自动代替的检查 |
|---|---|---|
| 整体完成后长什么样 | 本订单效果图，带版本 | 效果图不提供隐藏构件、孔槽或真实尺寸 |
| 这是哪个柜组、哪个位置 | 施工图中的柜号／轴线／视图，CAD 装配树 | 一个场景节点不一定是一件工件 |
| 有几件相同的东西 | 已核验订单 BOM；STEP 装配实例辅助计数 | 装配可能含备件、镜像件、抑制件或重复展示 |
| 加工尺寸、孔槽、封边、材料 | 标明对象和版本的工程图、原生参数／属性及人工确认 | 模型外包框、OCR 字符和视觉颜色均不能直接成为下料数据 |

## 可实施的八层流水线

1. **资料收件与版本锁定。** 按项目登记源文件 SHA-256、设计版本、来源角色、单位、页码或装配节点；同名新文件也要视作新版本。引用丢失、未确认单位或过期版本阻断后续生产发布。
2. **按格式解析。** 效果图仅用于外观；PDF/图片抽取原页、文字和位置，DXF 读取实体、图层、文字及尺寸对象；STEP 用 OCCT/XDE 读取 B-rep、装配树、实例和源属性。`.max` 原件需在装有 3ds Max 的工作机提取场景，SolidWorks 原件需使用有相应授权的软件或导出 STEP/BOM。
3. **几何与视图结构化。** 保留每个 STEP 实例的定义、路径、有效性、实体数、面积、体积及世界轴外包尺寸；对有效单实体再计算定向外包短／中／长边和薄板形态提示。对图纸保留标题栏、件号、尺寸标注及其在原页的坐标。所有几何值是核对证据，不是加工值。
4. **候选柜组和构件。** 先按装配定义与规范化实例名分组，不把不同名字的左右件硬合并。未来加入柜号、空间范围、材料属性和图纸件号关联；自动合并必须有可解释依据，无法确定时留多个候选。
5. **跨图纸匹配与冲突检测。** 硬约束为同项目、同版本、已确认单位、同件号／柜号或明确映射；软排序可用名称、几何比例、邻近标注、视图位置和装配层级。一个尺寸值要记录来源文件、页码／节点、原始文字、单位、归属对象及转换过程。不同来源冲突、多个候选分数接近时停止自动写入，展示对照让技术员决断。未来可用最小费用匹配求全局对应，但算法不能越过硬约束。
6. **人工确认制造数据。** 技术员看效果图、施工图、工程图和模型高亮，逐项确认数量、加工长宽厚、材料牌号、木纹／四边封边、五金、玻璃磨边和开孔、灯具回路、表面处理、公差及节点做法。界面默认留空未知字段，不能把“模型看起来像木板”填成材料。
7. **正式 BOM 和工序。** 审核后的构件映射本厂工艺模板，计算物料净需求并对库存与采购，生成木工、五金、玻璃、电工并行及总装依赖；人力、设备、物料到期日决定具体排程。任务工卡关联所需原图和构件位置。
8. **反馈闭环。** 记录技术员改掉了哪个候选、哪张图支持修改、现场缺料／返工原因与最终质量结果。按工厂和产品族训练匹配及规则，跨工厂数据不得混用。来源图纸修订时旧证据和审核应失效。

字段证据建议采用 `value / unit / source_sha256 / source_revision / page_or_node / raw_evidence / extraction_method / reviewed_by / reviewed_at`。数值、置信度和**工程师确认**是三种不同信息；OCR 的置信度不是尺寸正确率。

## 本版已经落地的 STEP 纵切

本地 Open CASCADE 引擎实际读取 STEP；完成且与当前登记文件 SHA 一致后，`GET /api/projects/{project_id}/engineering/{job_id}/proposals` 按定义和实例名产生可复现候选组。返回源长度单位识别状态、实例路径、建议实例数、世界轴及定向外包参考、薄板形态提示和需要核对的问题。每个实例还保留 XDE 中明确记录的上级装配名称和路径；同一候选跨多个上级装配时提示核对柜组，缺少父级记录时不猜测。当前不会因此自动分柜或改变候选数量。源单位未知或冲突时界面显式提醒；不妨碍技术员另据施工图填写加工数据。候选的材料、制造尺寸、工艺仍为空。旧的单实例 CAD 建件入口关闭，防止绕过组和数量确认。

同项目中已完成且仍与当前登记文件 SHA-256 一致的施工图 OCR 任务，现在可通过 `GET /api/projects/{project_id}/engineering/{step_job_id}/drawing-matches` 与 STEP 候选做只读关联。算法只认完整、足够具体的规范化名称或件号；把文字、原文件、原页码、图上位置和同一识别区域内的尺寸字符串显示为**疑似对应证据**。同件号可能指左右不同构件、同一处文字命中多个模型、同名存在不同尺寸或源版本失效时提示冲突／歧义。无原文件版本绑定的缓存图页不参与匹配。相邻但不在同一识别区域的尺寸不会被自动归给构件，也不会用 OCR 数字填加工字段。

技术员选择候选时，必须填订单数量、加工长宽厚、材料及业务必需字段，并确认数量和加工尺寸；新构件进入待审核。批准时要二次确认数量和尺寸，并写审核依据。重复提交同一个来源候选不重复造件。现有工程发布检查仍负责阻断未复核构件。定向外包和 OCR 尺寸即使与已知板材尺寸接近，也**不能**自动抄作下料长宽厚。当前跨图纸线索仅在核对界面展示，构件保存的结构化工程依据仍为 STEP 候选；审核说明由技术员写入。

这一步是真实 CAD 几何算法、保守跨图纸关联与可操作的审核闭环，但不是全格式、全工艺的自动 BOM。当前只关联 OCR 同一文字区域，尚不能确定尺寸线指向的构件，也没有可靠读取任意 `.max` 或 SolidWorks 原件的制造语义；不能报告真实客户订单的“拆单准确率”。队友提供的 ZIP 是暂定柜组出图结果，不含生成算法源码，参见[交接说明](队友出图流程接入说明.md)。

## 开源底座与商用边界

| 项目 | 适合的位置 | 商用／采用结论 |
|---|---|---|
| [Open CASCADE OCCT](https://github.com/Open-Cascade-SAS/OCCT) / [XDE](https://github.com/Open-Cascade-SAS/OCCT/wiki/xde) | STEP B-rep、装配、实例、几何检查；本版已接入 | LGPL-2.1 加 OCCT 例外。OCP Python 包装层为 Apache-2.0，不能替代内核及原生依赖的分发义务；见本仓库[许可核查](../open-source/开源使用与分发要求.md)。 |
| [ezdxf](https://github.com/mozman/ezdxf) | 下一阶段 DXF 图层、尺寸对象、块及件号抽取 | MIT。能读 DXF，不会理解展柜制造语义。 |
| [eDOCr2](https://github.com/javvi51/edocr2) | 评测机械工程图的尺寸文字与区域分割，可补充现有 PaddleOCR | [代码 MIT](https://github.com/javvi51/edocr2/blob/main/LICENSE)；模型权重及依赖另核，中文展柜施工图尚未验证，本版不嵌入。 |
| [FreeCAD TechDraw](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/TechDraw_ProjectionGroup.md) | 从**已审核几何**生成多视图供技术员编辑 | FreeCAD LGPL2+；不是任意图纸转制造 BOM。 |
| [CadQuery](https://github.com/CadQuery/cadquery) | 标准柜族的参数化模板和复用 | Apache-2.0；适合已知规则的柜型，不能逆向猜出任意项目设计。 |
| [trimesh](https://github.com/mikedh/trimesh) | `.max` 导出网格的空间与连通性分析 | MIT；连通网格不等于生产构件。 |
| [UV-Net](https://github.com/AutodeskAILab/UV-Net) | 将来有本厂标注样本后做 B-rep 特征／部件辅助分类 | MIT 研究代码，需自建训练、评估和运行管线，本版未嵌入。 |

[BRepNet 官方许可](https://github.com/AutodeskAILab/BRepNet/blob/master/LICENSE)是 CC BY-NC-SA 4.0，不能直接作为商用 KANPACE 的内嵌算法。原生 SolidWorks/3ds Max API 和 NVIDIA CAD 转换运行时也不能因为能在本地调用就称为开源。所有开源依赖在实际打包分发前仍按版本核对许可、模型权重及内嵌原生库。

## 真实订单验收，而不是演示截图

用至少三单有**效果图＋施工图＋工程图＋人工确认 BOM** 的历史订单做盲测；如果要验证 STEP 几何，另需取得该订单真实 STEP/完整装配及外部引用。请技术员先建立金标准：柜组边界、构件清单、件号、数量、材料、加工尺寸、工艺、需看的图页。指标分开统计：柜组召回率、构件精确率与召回率、数量误差、关键尺寸冲突检出率、字段有据率、每单复核时间、工程师改动数以及从审核到派工所需时间。必须额外做以下安全门槛：未知单位／过期版本／缺失材料或尺寸／未批准候选 **0 次生产发布**；图纸修订后旧审核不能继续放行。

合成 STEP 测试已覆盖装配重复实例、中文名、英寸换算、坏文件和旋转薄板的定向外包。另一次隔离实测使用真实 STEP 工作者和本地 OCR 工作者处理同一演示项目的模型与工程图，OCR 读到 `Panel-A 1200 x 550 x 18mm`，跨图纸接口返回 1 条疑似关联，`manufacturing_release=false`。这些测试证明底层读取、来源校验和只读关联可工作，不能替代上述真实订单验收。
