## 实际实现

1. 新的十步订单工作流页面及深链接，默认浏览器入口，当前订单和工程版本明确展示；原业务操作页面继续承接实际审核与执行。
2. 只读流程投影由真实资料、构件、任务、物料、预览和采用记录计算。未知时长、尚未审核尺寸、缺料或版本变化会形成待处理事项，不能因界面进度而越过业务门槛。
3. 统一识别后台任务：上传原件副本、固定 source identity/hash/revision、持久结果、逐文件检查点、继续未完成资料、最大页数、并行与超时限制。
4. 原生 TXT/CSV/TSV/XLSX/JSON/PDF 解析；PDF 提取真实字符/词框，CSV/XLSX 保留单元格，公式保留原文而不执行。EvidenceRef 经 Store 导入/重读保留来源；识别不自动批准构件或发布 BOM。
5. 固定 worker 协议与服务就绪检查。Docling CPU worker 使用完整标准 pipeline；PP-OCR server/PaddleOCR-VL 的入口在真正服务就绪之前明确待配置。像素坐标与 PDF point 坐标不混合。
6. OR-Tools 真实 CP-SAT 排程和独立校验；启发式回退也校验约束并记录真实引擎状态。LangGraph 真实跨进程 SQLite checkpoint 恢复，不调用通用模型，不自动采用生产方案。
7. 显式 authenticated Web mode：合法 HTTPS public origin、有效管理员、精确 Host/Origin、Secure cookie、整单权限与 CSRF 边界；伪造代理头不能绕过配置。开发 loopback 与认证 Web 模式分别标识。
8. 浏览器订单切换和登出作废旧响应，隐藏页面停止轮询，提交与刷新并行不会卡住写状态；网络读取失败不会伪造失败任务或提供不存在的恢复入口。

## 部署与许可边界

本次实测是 macOS/Python 3.12 CPU 环境，Linux 云服务器要重新安装和运行同一探针，不可复制 macOS venv。主业务存储仍为 SQLite，后台任务仍是现有单服务进程；PostgreSQL、多副本队列、Temporal、对象存储和 10–30 人并发压测尚未实施。现阶段可作开发/单服务部署验收，不宣称已达云集群生产级容量。
