# KANPACE 组织资源与企业流程接口

实现：`operations.py`。调用方在同一个 SQLite 写事务内执行，遇到 `OperationError(status,message,details)` 回滚。此模块不读取设备密钥、不下发硬件、不在读取时创建真实组织或改写旧数据。

## 组织资源

`GET /api/operations?factory_type=cabinet|machinery|site&include_demo=0|1`

返回 `factories, teams, workcenters, people, templates, workflows, builtin_templates, trade_catalog`。未归属的真实旧员工仍可见；默认不显示演示人员。三套内置行业参考只读，估计工时全部为空，必须复制、核对并发布为企业模板。

| POST 路径 | 主要参数 | 返回 |
|---|---|---|
| `/api/operations/factories[/{id}]` | name, factory_type, note | factory |
| `/api/operations/teams[/{id}]` | name, factory_id, leader_id, note | team |
| `/api/operations/workcenters[/{id}]` | name, factory_id, team_id, kind:equipment/station/area, capacity_minutes, note | workcenter |
| `/api/operations/people[/{id}]` | name, role, skills, factory_id, team_id, capacity_minutes | person |

更新必须携带 `expected_version`。容量未知保留 null，不能用默认 480 分钟虚构产能。技能支持规范的非空自定义工种。工厂、班组、工位、人员的显式归属必须一致；对仍有在途任务的人员，不能直接移除对应技能或移出项目所属工厂。

`assignment_issues(project,person)` 用于现有分派、自动分派、开工和排程路径。旧未归属项目保留兼容性，新显式归属项目不能使用异厂或未归属人员。演示数据与真实数据不混用。

## 模板

- `POST /api/operations/templates`：`name,factory_type,factory_id?,nodes,note,source_template_id?`。
- `POST /api/operations/templates/{id}`：更新草稿，带 expected_version。
- `POST /api/operations/templates/{id}/publish`：带 expected_version，发布为不可变版本。

节点字段：`id,name,trade,predecessors,start_checks,acceptance,instructions,estimated_minutes,quality_gate,workcenter_id`。节点编号唯一，依赖必须存在且无环。发布要求每个节点具有明确验收内容。`estimated_minutes` 是人工配置的每工作对象分钟数，未知保留 null。`quality_gate` 标记需要检验放行的节点。

发布版不可修改，通过 `source_template_id` 复制为下一草稿版本。发布内容保留 SHA-256，项目固定引用发布版，不追随之后的草稿修改。

## 工作包草稿、复核与发布

`POST /api/projects/{project_id}/workflow`

```json
{
  "template_id": "已发布企业模板ID",
  "factory_id": "真实工厂ID",
  "expected_revision": 1,
  "expected_version": 0,
  "scope_note": "已确认施工图R1对应柜号A01-A02的人工工作包",
  "objects": [{
    "code": "A01",
    "name": "一号柜",
    "location": "一层A区",
    "quantity": 1,
    "unit": "柜",
    "instructions": "本对象明确技术要求",
    "document_ids": [],
    "batch_code": "第一批",
    "delivery_group": "首车"
  }]
}
```

返回 `workflow,tasks,project`。每个独立工作对象生成一份 DAG，分批工作独立执行；同对象前序映射到真实任务 ID。任务携带对象编号、位置、工作要求、来源、模板版本、开工检查项、验收要求、批次及工作中心。未知时间仍为 null。整数 quantity 表示完成几个工作对象；施工面积不等价于此整数完成数。

该入口是人工工作包编制，不宣称图纸自动拆单。已存在的普通生产任务或已开工工作包不能被覆盖。草稿修改会归档旧草稿并撤销复核状态。

`POST /api/projects/{id}/workflow/review` 参数：`expected_version,reviewer,review_note,acknowledge_manual_scope:true`。每个对象必须有来源文件或明确技术要求；引用文件必须属于本项目。复核仅确认草稿，不发送任务、不改变实际完成量。

最后调用现有 `POST /api/projects/{id}/release`。集成要求：调用 `release_blockers(store,con,project)`；无 BOM 的已复核工作包可以走手工任务路径；已有 BOM、施工图转换/补录核验和工程版本检查必须保留。任务之后沿现有派工、开工、暂停、报工、检验、完成路径执行。

## 版本迁移

- `POST /api/projects/{id}/workflow/preview {template_id}` 返回增加、删除、变化节点、受影响和保留任务、阻断项、当前版本及 `impact_token`。
- `POST /api/projects/{id}/workflow/migrate {template_id,expected_version,expected_revision,impact_token,review_note}`。

变化影响向下游依赖传播；预览 token 包含所有当前任务执行版本，任务变化后须重新预览。任何执行中工序须先暂停交接；受影响工序如已有实绩，禁止自动迁移，应明确返工或另建工作范围。允许迁移时创建新工程版本和待复核工作包，旧任务与原工作包保存历史，未受影响的已完成工序继承实绩，不重新派做。

迁移之后必须重新复核发布。未受影响的暂停工序记录 `carried_status`，现有发布路径应恢复 blocked，不能自动将其放行为 ready。

## 验证

`python -m unittest discover -s tests -p test_operations.py -v`：16 项隔离数据库测试，覆盖三行业 DAG、来源归属、未知工时、并行对象、重复对象、发布不可变、环依赖、工厂隔离、在途人员保护、乐观锁、迁移影响传播、旧预览拒绝及已完成实绩保留。

返工迁移补充：任何未完成返工都会阻断迁移；已完成返工在 historical_reworks 单独展示，保留原任务与实绩，不参与普通工序承接键匹配。原任务质量暂停依据继承到新版本，不能利用迁移清空质量门槛。
