# KANPACE 开源使用与分发要求

版本：2026-09-07。适用范围是当前 KANPACE 源码交付和现有依赖基线。自有代码授权见根目录 `LICENSING.md`；汇总声明见 `THIRD_PARTY_NOTICES.md`；逐项版本和分类见 `third-party-components.json`。本文件是工程交付说明，完整许可证原文优先。

## 1. 这次交付到底包含什么

| 类别 | 当前处理 | 交付者需要保留的内容 |
| --- | --- | --- |
| KANPACE 自有 Web、后端、适配器源码 | 包含 | 自有代码说明、使用/安装文档。交付源码不等于对全社会授予 MIT/Apache 许可 |
| Three.js JS 与 occt-import-js JS/WASM | 包含，未修改上游文件 | 原始版权/许可、`licenses/web/` 内对应源码与构建材料、替换说明 |
| ESP32 源码、现有固件及位图字库 | 按固件清单交付 | `firmware/goldenmorning-display/THIRD_PARTY_NOTICES.md` 及其许可/构建材料 |
| Paddle/OCP/OR-Tools/LangGraph Python 环境 | 不包含 `.venv*` 或 wheel | 安装器、固定版本锁文件、归档许可证。安装时在收件人机器上下载 |
| Paddle OCR 模型权重 | 不包含 | 两个默认 mobile 模型的精确 revision、文件哈希和模型卡；安装器按固定版本下载 |
| PackingSolver 本地程序与大型源码/构建树 | 不包含 | 固定提交、构建安装器、构建选项和依赖许可。当前后端 HiGHS，CLP/KNITRO 未启用 |
| 各工厂订单、图纸、预览、数据库、Wi-Fi 密码 | 不包含在通用源码包 | 单独授权的工厂备份流程，不纳入第三方开源源码或模型 |

机器清单中的 `distribution` 是实际交付分类：`source`=随附可读源码；`binary`=随附编译产物；`vendored`=已复制的上游文件；`downloaded`=安装或构建时从上游取得；`local-only`=当前开发机有，但本通用源码包没有。一个组件可以同时具有多个分类，例如浏览器 WASM 是 `vendored + binary`，它的对应源码另以 `source` 提供。

安装器联网下载上游依赖不需要上传客户资料。若交付方案改变为“离线一体化安装包”，就成为另一组实际分发物，应重新按二进制、嵌入库、模型、字体分别审查；不能沿用本次“未随包”结论。

## 2. 五个引擎如何商用

**PaddleOCR / PaddlePaddle / PaddleX：Apache-2.0。** 允许商业使用和分发。保留许可、版权及适用 NOTICE；修改上游文件时标注修改。默认检测和识别模型分别锁到 `0d63e78…`、`682f205…`，其官方模型卡各自声明 Apache-2.0。未来换成 VL、v6、第三方微调模型或其他下载来源，需要重新检查那一组权重的许可，不能继承 PaddleOCR 代码的许可。[Apache 原文](https://www.apache.org/licenses/LICENSE-2.0)、[mobile_det 精确模型卡](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_det/blob/0d63e78e2b680928f6b1747d76a08db6e645efb7/README.md)、[mobile_rec 精确模型卡](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec/blob/682f20538d8c086cb2128e5cfac775e6c4904e85/README.md)。

**后端 OCCT：包装器和内核分开。** `cadquery-ocp 7.8.1.1.post1` 的 Python 包装层是 Apache-2.0，内嵌 OCCT 7.8.1 是 LGPL-2.1 加 OCCT 例外。商业应用可以使用 LGPL 库，但分发库或包含库的二进制时，仍需相应版权声明、完整许可、对应库源码以及适用的修改/替换/调试条件。OCCT 例外不把整个内核变成宽松许可。当前源码交付没有附 OCP wheel。[OCCT 7.8.1 许可](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_8_1/LICENSE_LGPL_21.txt)、[OCCT 例外](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_8_1/OCCT_LGPL_EXCEPTION.txt)。

**OR-Tools：Apache-2.0；PackingSolver：MIT。** 自有排程/排料规则可以独立维护，不能抹掉 Google、PackingSolver 作者及依赖作者的许可。当前 PackingSolver 源码和 8 个 Git 依赖工作树均核验无修改，构建开关记录为 HiGHS 开、CLP/KNITRO 关；启用新后端必须连同依赖重新核验。HiGHS 内部 AMD/METIS 等有自己的 BSD/Apache 条款，Boost 为 BSL-1.0。逐一文本在 `licenses/optimization/cpp/`，不能只随附一份 PackingSolver MIT。[OR-Tools v9.15](https://github.com/google/or-tools/blob/v9.15/LICENSE)、[PackingSolver 固定提交](https://github.com/fontanf/packingsolver/blob/4ba84e45ab4b7697d2fec2bb62bdca09dab56d29/LICENSE)。

**LangGraph：MIT。** 本项目把它用于本机工作流，不包括 LangSmith 云服务授权，也没有随附大语言模型。MIT 允许商业集成并要求保留版权/许可；依赖仍须逐项处理，例如 `orjson` 的声明含 MPL-2.0 与 Apache/MIT，`certifi` 为 MPL-2.0，不能一起改标 MIT。两个原发布包未携带许可文件的依赖（LangSmith SDK 0.12.2、sqlite-vec 0.1.9）已从其精确官方版本补充原文，来源在运行时许可证目录的 supplemental JSON 中。[LangGraph](https://github.com/langchain-ai/langgraph)、[LangSmith SDK v0.12.2 许可](https://github.com/langchain-ai/langsmith-sdk/blob/v0.12.2/LICENSE)、[sqlite-vec v0.1.9](https://github.com/asg017/sqlite-vec/tree/v0.1.9)。

## 3. 浏览器 WASM 已随附完整来源，不能只留网址

浏览器端的 occt-import-js 0.0.23 使用 **OCCT 7.6.1**；后端使用 7.8.1，两者独立记录。本次已在 `licenses/web/` 附：

1. 官方 npm 包 `occt-import-js-0.0.23.tgz`，含 C++ 源码、CMake 配置和原始构建脚本。
2. OCCT 精确子模块 `d2abb6d844231cb8f29be6894440874a4700e4a5` 的完整官方源码归档，约 46 MB。
3. LGPL 文本、原来 vendor 目录未带的 OCCT 例外，以及 Emscripten 3.1.69 的相关运行库许可。
4. 源码对应关系、npm integrity、14 个 vendored 文件的 SHA-256 检查、编译及替换步骤。

这些源文件必须随 WASM 一起交付；不能从包中删去归档而继续宣称已提供对应源码。保留独立 JS/WASM 文件和 Worker 调用结构，允许收件人替换修改后的兼容库。若自有授权条款含禁止反向工程，应明确保留第三方 LGPL 库调试修改所需的例外。源码已核验与发布相符，但本次未重建，未承诺新主机生成相同 SHA-256。详细步骤见 `licenses/web/README.md`。

## 4. 原生库里还藏有哪些许可

Web 基础依赖单列在 `licenses/web-runtime/`：pySerial 3.5 为 BSD-3-Clause，Web Pillow 当前 12.3.0 为 MIT-CMU；Web 安装器使用 `>=12.0,<13` 范围，工程环境则独立固定为 11.3.0。Poppler 的 `pdfinfo`、`pdftoppm` 本机为 26.04.0，是以 subprocess/文件接口调用的外部 GPL 命令，未打包其可执行文件或链接库。已保留实际安装包的 COPYING/README 和上游精确版本 COPYING。未来若附送它的二进制，需要对应 GPL 源码与许可材料；若改成直接链接，更需重新审查组合方式。本次没有把 KANPACE 的自有许可自动改为 GPL。[pySerial 3.5 许可](https://github.com/pyserial/pyserial/blob/v3.5/LICENSE.txt)、[Pillow 许可说明](https://pillow.readthedocs.io/en/stable/about.html#license)、[Poppler 官方项目](https://poppler.freedesktop.org/)。

`licenses/engineering/embedded-ocp-native-libraries.json` 记录当前 OCP wheel 内 75 个 `.dylib` 的文件与哈希。它们不是 75 个全部 Apache 的独立产品，清单也不是完整二进制分发合规证明。

- **FreeImage 3.18.0：选择 FIPL 1.0。** 上游提供 FIPL/GPL 双许可，本项目按适合商业应用的 FIPL 路径说明。需要随附所选完整许可，并在用户手册/关于中承认使用 FreeImage；分发受覆盖源码、修改和可执行形式时，遵守该许可的通知及源码可得性条款。根 `THIRD_PARTY_NOTICES.md` 已加入明确致谢。[上游许可说明](https://freeimage.sourceforge.io/license.html)、[FIPL 原文](https://freeimage.sourceforge.io/freeimage-license.txt)。
- **LibRaw 0.21.3-Release：LGPL-2.1 或 CDDL-1.0。** 两条都允许在满足条件时商用，具体分发应选明路径。CDDL 对其覆盖文件/修改和可执行形式分发有源码可得性等要求；LGPL 另有链接/替换条件。两者都不是“随便复制的 Apache”。目前 archive 保存两套原文与上游 COPYRIGHT，不替交付方隐式选成 GPL。[LibRaw 0.21.3 COPYRIGHT](https://github.com/LibRaw/LibRaw/blob/0.21.3/COPYRIGHT)、[CDDL](https://github.com/LibRaw/LibRaw/blob/0.21.3/LICENSE.CDDL)、[LGPL](https://github.com/LibRaw/LibRaw/blob/0.21.3/LICENSE.LGPL)。
- **需要关闭的缺口：** 当前 wheel 的 FreeImage 3.18.0 链接 LibRaw 0.21.3，和旧版 FreeImage 官方源码包原有的 LibRaw 版本不同；仅下载旧 FreeImage 源码不能证明获得该 wheel 的完整对应源码与补丁。LibRaw 可选 GPL demosaic 包的构建配置也未从此 wheel 完整证明。未来再分发原生包之前，应取得构建清单、源码和补丁并核对该配置。详见 `licenses/engineering/embedded-native-distribution-audit.md`。
- **PDFium/OpenCV/VTK 等：** 其 Python 包装器、原生库和嵌入组件分别有 Apache、BSD、MIT、Libpng、IJG 等文本。当前归档保留供应方给出的完整第三方通知，跨平台换 wheel 后需要重新生成许可清单；此处没有把包装器许可当作全部原生库的许可。

上述缺口不应被写成“本机不能运行”，也不应被写成“原生一体化安装包已完成商用分发审核”。本次源码包排除它们，收件人在本机依固定版本安装。

## 5. 字体、品牌、数据的边界

Web 页面没有打入原始字体文件，使用系统字体。不能从 `PingFang SC` 或 `Microsoft YaHei` 这样的 CSS 名称推导出字体可被复制给客户。开发机生成的文档工具也可能调用系统字体，若改变为分发字体源文件，需要先核对该字体的实际授权。

ESP32 使用的字体和字形子集以固件清单为准。对于确认为 **SIL OFL 1.1** 的原字体：随软件一起分发可行，需要保留原版权和 OFL；单独出售字体不可行；修改/子集化/格式转换属于修改版本，须处理 Reserved Font Name 约束，不得声称原作者为修改版背书。文档、图片和使用字体的应用本身不因此自动变成 OFL。[OFL 官方全文](https://openfontlicense.org/open-font-license-official-text/)。

KANPACE 品牌资产来自本项目使用者指定的品牌资料，没有在本第三方清单中另授商标或公开开源权利。工厂图纸、BOM、工时、生产记录也不因开源引擎被安装而授予其他工厂使用、训练或复制的权利。

## 6. 维护人员的具体操作

1. 发包时将根声明、机器清单、`licenses/`、LangGraph 运行时许可目录和固件声明同时保留；验证归档内列出的路径存在。
2. 不把当前机器的 `.venv*`、模型、wheel 或优化器程序临时复制进本源码包。若确有离线部署需求，先建立另一套明确包含这些文件的组件清单，关闭原生分发缺口。
3. 改版本、模型 revision、浏览器 WASM 或求解器后端时，更新锁文件、模型哈希、上游来源、许可文本、修改记录和原生验证；只改界面显示版本不算更新来源证据。
4. 若修改上游库，把修改文件、日期、补丁和构建开关写进组件清单。自有适配器与上游未修改文件分别记录。当前四个引擎适配器仅增加许可指引注释，不改变执行行为。
5. 不能对外笼统宣传“所有开源依赖都是 MIT”“所有权重随代码 Apache”“整个固件闭源且禁止替换第三方库”或“引擎作者为 KANPACE 背书”。按实际许可和证据表述。

## 7. 证据完整性的限度

此清单包含已安装 Python 包的元数据/原文、官方精确版本补充文件、上游源码提交、模型卡、二进制哈希与人工核验重点；不是独立许可证扫描器出具的法律认证。源码包不包含的本机二进制仍被登记，是为了后续交付时避免漏项。机器清单将 `observed_license_metadata` 和已人工核验的主要组件分开，原包可能有遗漏或许可证元数据不完整，应继续以源码文件和完整通知为准。
