**KANPACE 五项核心开源选型**  
核验日期：2026 年 9 月 7 日

建议集中投入 **PaddleOCR、完整后端 OCCT、Google OR-Tools、LangGraph、PackingSolver**，分别补齐读图、工程几何核对、排产优化、多步骤操作助手、材料排料。这五项覆盖“少拆错、少延期、少操作、少浪费”，比继续增加通用管理菜单更接近老板愿意付费的结果。

本报告根据 KANPACE 当前源码、已有开源清单及上游官方资料作出选型。**本轮没有安装这些候选、没有用真实订单跑准确率或性能对比，也没有取得节省百分比。** 以下能力是开发基础与验收方向，不能当成已经交付的效果。

| 入选项目 | 给工厂的直接价值 | 团队性质 | 主要许可 |
|---|---|---|---|
| PaddleOCR | 施工图文字可提取、可定位复核 | 百度飞桨团队 | Apache-2.0；具体模型分别核验 |
| 完整后端 OCCT | 依据真实工程模型核数量、尺寸与版本 | 专业 CAD 内核团队 | LGPL-2.1 加特别例外，另有商业许可 |
| Google OR-Tools | 对比可行排程，处理急单和资源冲突 | Google 运筹优化团队 | Apache-2.0 |
| LangGraph | 一句话串起查询、分析、方案和确认 | LangChain 官方团队 | 核心库 MIT |
| PackingSolver | 减少板材、玻璃、型材损耗 | 有竞赛与论文成果的优化专家 | 主项目 MIT，依赖另核 |

**1．PaddleOCR：先让施工图中的关键数字有依据。**

KANPACE 已能保存原图、展示图文、管理构件和工程版本；扫描图的关键文字提取、引线归属和冲突核对仍需补强。PaddleOCR 可提供文字及位置，适合识别料名、厚度、数量、编号和尺寸原文。百度飞桨维护完整训练、部署和文档管线；官方已发布 PP-OCRv6，旧清单中的 v5 不应称为最新版。[官方仓库](https://github.com/PaddlePaddle/PaddleOCR)

试点先锁定 PP-OCRv6_medium_det 与 medium_rec，保留 v5 作对照。代码及这两个官方权重均标明 Apache-2.0，可商业集成；交付保留许可、适用版权和 NOTICE，注明修改。方向分类、表格、视觉语言模型及其他依赖按实际选用范围另核，不能沿用同一个许可结论。[代码许可](https://github.com/PaddlePaddle/PaddleOCR/blob/main/LICENSE)、[检测权重](https://huggingface.co/PaddlePaddle/PP-OCRv6_medium_det)、[识别权重](https://huggingface.co/PaddlePaddle/PP-OCRv6_medium_rec)

接入时保存“原文、页码、坐标、模型版本、识别分数”，点选字段即可回到原图。KANPACE 自建直径、公差、单位、总体尺寸与下料尺寸的区分规则；同件多视图不能累加数量，冲突与缺失进入复核。验收看关键字段漏检、数字错误和人工核对时间，单独检查 Ø、±、R、上下偏差；公开 OCR 榜单不能代替本厂工程图测试。未确认数字不得进入下料或正式报价。

**2．完整后端 OCCT：从能旋转观看，走向能核对工程事实。**

当前 Web 已有 Three.js 和 occt-import-js，主要消费网格及层级结果。新增价值应放在后端保留真实 B-rep 实体、拓扑及 XDE 装配数据，核对单位、实例数量、面积、体积及受支持属性，绑定源文件版本。Open Cascade 是专业 CAD/CAM/CAE 内核团队，官方有持续版本维护。[官方仓库](https://github.com/Open-Cascade-SAS/OCCT)、[8.0.1 发布](https://github.com/Open-Cascade-SAS/OCCT/releases/tag/V8.0.1)

标准交换以 STEP、IGES 等为主；支持部分 AP242 与受支持的工程标注，不代表完整 SolidWorks 参数树、配合关系或通用 DWG。原生 SolidWorks 继续沿用 Windows 导出桥接；效果图用于展示，不能反推未经验证的加工尺寸。[STEP/XDE 官方说明](https://occt3d.com/dev/doc/overview/html/occt_user_guides__step.html)

OCCT 可商用，许可为 LGPL-2.1 加特别例外。闭源交付仍需履行库源码及修改、许可、可替换或重新链接等适用义务；例外没有把整个库变为 MIT。建议采用清晰可替换的独立进程或动态库，并整理对应源码及许可；也可采购商业许可，专有交换组件另算。[LGPL 正文](https://github.com/Open-Cascade-SAS/OCCT/blob/master/LICENSE_LGPL_21.txt)、[特别例外](https://github.com/Open-Cascade-SAS/OCCT/blob/master/OCCT_LGPL_EXCEPTION.txt)

KANPACE 仍要自建零件身份、封边/焊接/玻璃工艺映射、版本变化与任务影响关联。验收使用工程师核定模型，对照单位、实体与实例数量、测量误差、无效几何和版本漏报；不能把近似网格测量标成工程精度。

**3．Google OR-Tools：让排程比较方案，而非只按顺序塞时间。**

现有排程已有前序、人员与工作中心占用、预计到料、冻结方案和插单试算；当前主要按状态、优先级和交期贪心安排。OR-Tools 可表达可选人员/设备、累计容量、不可重叠区间和日历，联合比较延期、换型、加班及改期扰动。它由 Google 维护，CP-SAT 可本地运行，不要求采购商业求解器后端。[官方仓库](https://github.com/google/or-tools)、[排程建模文档](https://github.com/google/or-tools/blob/stable/ortools/sat/docs/scheduling.md)

主项目 Apache-2.0，可用于商业产品，交付履行许可、适用 NOTICE 和修改说明等要求，打包依赖一并归档。[许可证](https://github.com/google/or-tools/blob/stable/LICENSE)

KANPACE 提供每厂班次、技能资格、设备能力、工艺时长、物料预留及目标权重；特别区分加工、等待、固化和跨班规则。求解器接收带版本的快照，返回候选方案，独立业务校验后再确认发布。超时或未知状态不可标为最优，旧快照拒绝发布，保留原算法回退。

验收同一输入对比现有算法和计划员方案：人员/设备冲突、前序违规、冻结工序被移动、库存超用均应为零，再比较延期分钟、改期数量、加班和求解时间。安装求解器不会自动补出缺失工时，也不等于已具备完整 APS。

**4．LangGraph：把操作助手变成可靠的多步骤工作入口。**

当前助手是本地规则指令解析，没有通用模型推理。LangGraph 能编排“查延期→查原因→调用排程→展示差异→确认执行”，并支持保存状态、等待人员复核和恢复。LangChain 官方团队维护；可独立嵌入现有服务。[官方仓库](https://github.com/langchain-ai/langgraph)、[持久化](https://docs.langchain.com/oss/python/langgraph/persistence)、[中断与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)

核心库 MIT，商业嵌入需保留版权及许可；LangSmith 私有化是另外的企业付费产品，不能混称免费开源。中文理解还需选择模型并核对其权重或 API 条款，框架本身不会让工程判断更准确。[核心许可](https://github.com/langchain-ai/langgraph/blob/main/LICENSE)、[LangSmith 私有化授权](https://docs.langchain.com/langsmith/self-hosted)

KANPACE 自建受控工具、字段校验、来源引用和清晰的方案卡片。继续使用现有岗位权限、版本校验和生产门禁，断点重放用幂等控制防止重复任务；工人不会因一句含糊话被自动恢复、改量或派工。验收覆盖否定指令、同名任务、文件中的伪指令、越权、重启与重复请求；统计完成一次工作所需点击及误操作，不能只看聊天是否流畅。

**5．PackingSolver：让材料节省可以按金额验收。**

当前已能按构件计算材料及估价，但缺少可核查的优化下料布局。PackingSolver 提供一维下料、矩形、齐头切、异形和箱体装载等求解器，可输出布局证据。先做矩形板材、玻璃及型材，再评异形与装载。[官方仓库](https://github.com/fontanf/packingsolver)

这是优化专家项目，维护集中度高，不能包装成 Google 规模的大公司。作者 Florian Fontan 与 Luc Libralesso 获 ROADEF/EURO 2018 Saint-Gobain 切割优化挑战总排名第一，是可查的专业能力证据，不能代替 KANPACE 订单成绩。[主办方最终结果](https://roadef.org/challenge/2018/en/finalResults.php)

主项目 MIT，可商业集成并保留版权与许可；启用第三方求解后端时另核依赖条款。[许可证](https://github.com/fontanf/packingsolver/blob/master/LICENSE)

输入只能是审核后的下料尺寸和数量。KANPACE 自建材料/厚度分组、纹理方向、锯缝、裁边、加工余量、缺陷和余料规则；成品外形、OCR 未确认尺寸、未展开钣金不能直接排料。输出不等于可靠机床程序。选至少十批历史订单，在相同约束下对比：数量完全一致，重叠、越界及不可加工布局为零，再核板数、采购成本、可用余料及人工修改时间，不能只追求填满率。

**其他候选为何暂不占名额。** Qdrant 成熟且 Apache-2.0，但此刻先把工程资料结构化、复核和回链做实；料号、库存和准确尺寸用关系数据库，语义找相似案例经对照测试有增量时再引入。[Qdrant 官方仓库](https://github.com/qdrant/qdrant) Docling 是 IBM Research 发起的强项目，表格和文档结构化很有价值；第一批先集中验证中文施工图，避免同时维护两套重叠管线，后续再补复杂表格。[Docling 官方仓库](https://github.com/docling-project/docling) LVGL 适合后续复杂屏幕控件，当前胸牌更需要正确图纸、少页面、可读性和可靠报工，更换界面库不是新增制造壁垒。[LVGL 官方仓库](https://github.com/lvgl/lvgl) NVIDIA CAD 转 USD 新版可独立运行、不再要求 Kit，但运行时包含 NVIDIA 专有条款及 HOOPS，不能按 skill 许可称全开源；其平台与再分发条件需要单独评估。[运行时许可](https://github.com/NVIDIA-Omniverse/usd-convert-cad/blob/main/LICENSE.md)

落地先选一个综合展柜典型订单，从原图和已审核零件清单跑通读图、核模与排料；再用多订单、真实班次和到料日期比较排程，最后由助手串起已验证能力。机械设备和工程现场复用底层工具，分别配置装配测试、现场交接和资源规则，不能直接复制展柜流程。

**真正应积累的资产与保密边界。** 五个开源项目谁都能获得，排他优势来自 KANPACE 的“原图证据—构件身份—工艺规则—下料与排程—实际报工—纠错”关联、行业验收样本和简单稳定的使用流程。资料、标注、嵌入向量、模型微调产物、工艺参数、价格、日志及备份都属于相应工厂，按客户独立私有保存；不能自动汇入公共知识库或给其他工厂使用。通用应用代码和无客户数据的行业模板可以共用。商业交付按锁定版本保留许可证、模型卡、依赖清单及来源，升级后重新验证关键样本。
