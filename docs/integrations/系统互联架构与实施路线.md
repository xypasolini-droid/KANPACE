# KANPACE：在客户现有系统中提升展示柜生产效率

核查日期：2026-09-04。本文为产品与实施设计，未标记为已实现的连接器均尚未连接客户系统。厂商证据和产品版本边界见同目录调研矩阵。

## 产品定位与分工

KANPACE承担展示柜行业的图纸理解、构件拆分、工艺规则、工种任务、图纸变更影响分析，以及现场任务触达。客户继续在原有 ERP 开订单、在既有审批流程中确认 BOM 和采购、在原有报表中看结果。已经有 MES 的工厂继续使用该 MES 的工单与报工口径；没有 MES 的工厂可使用KANPACE作为轻量执行入口。

这项定位是本项目的设计选择，不是已经证明优于所有 ERP/MES 的性能结论。竞争力应通过真实订单试点验证：重复录入次数、拆单耗时、错版派工次数、报工到账延迟和对账差异。先测基线，再比较；不预设未经验证的降本百分比。

## 不同客户的接入方式

| 客户当前习惯 | 保留的入口 | KANPACE增加的工作 | 结果回到哪里 |
|---|---|---|---|
| Excel＋微信 | 原有订单表、群沟通 | BOM 文件映射、复核、工种拆单、设备任务 | 原格式任务/进度文件；消息入口待企业协同平台授权接入 |
| 金蝶、用友等 ERP，无 MES | 原 ERP 销售、库存、采购及财务 | 读取已审核订单与基础资料，形成有来源的 BOM 草稿及工种任务 | ERP 接受的 BOM/生产单/报工对象；先草稿、沿用原审批 |
| ERP＋黑湖/其他 MES | 原 MES 工单、排程与报工 | 为 MES 提供图纸拆单结果、工艺建议、任务说明；工牌接收获准的 MES 工序 | 报工仍由原 MES 记账；KANPACE保存映射、设备回执与辅助证据 |
| SolidWorks＋PDM | 设计师原软件、签入和版本发布习惯 | 从已发布模型配置/BOM取得构件，保留原料号与图纸版本，算出变更影响 | PDM 的关联记录或 ERP/MES 草稿，不覆盖已发布源图 |
| 海外 ERP 或集团 WMS/SCM | 原组织、工厂、币种与权限范围 | 以订单行和工序关联；接入已购中间平台 | 原业务系统及其审计记录，不由本地缓存替代库存账 |

Excel 是过渡入口，也可以是长期受控入口；CSV/JSON 导入导出已实现，按客户模板自动监视目录与回写尚未实现。普通微信个人账号不能按企业开放平台能力承诺自动化读写。

## 业务闭环示例

1. 客户在原 ERP 审核一张「珠宝中岛柜 10 套」订单，保留原订单号及行号。
2. 本地连接器读取该订单及已发布 R3 图纸/BOM。KANPACE区分每套 2 块侧板与整单 20 块，保留原件与单位依据。
3. 技术员复核木作、五金、玻璃、灯光构件和工艺。生成木工开料/铣槽钻孔/封边、金属加工、玻璃处理、电气装配等任务，并核对前后依赖。
4. 形成原系统可接收的 BOM、工艺或工单草稿。沿用该工厂既有的审核/发布权限；低风险自动同步可由管理员预先授权，不要求每条重复确认。
5. 已有 MES 时由 MES 发布可执行工序，再送到对应工种设备；没有 MES 时由KANPACE已发布版本派发。
6. 未来工牌报工形成带任务版本、数量、操作员及事件编号的执行事件，校验后送回唯一记账系统，显示「待回写/已记账/需处理」。当前工牌只接收任务，尚不能以按键报工。
7. ERP/MES 返回单据或报工编号后，KANPACE对账并关联。设备「已接收」与生产「已完工」严格区分。
8. R4 改图时，根据构件与工序映射列出受影响范围，处理未开工、在制和已完工三种情况；不把 R3 的在途报工无条件归到 R4。

## 数据主责与映射

每个字段/动作指定一个主责系统，避免两边同时改同一个数量或状态。以下是试点默认值，实施时按客户现状调整。

| 数据 | 默认主责 | KANPACE需要的映射与行为 |
|---|---|---|
| 客户、销售订单、订单行、交期 | ERP | 组织/账套＋单据 ID＋行 ID；沿用原编号并深链回原系统 |
| 料号、计量单位、仓库、批次 | ERP/主数据平台 | 原编码不重建；采购单位、库存单位、工艺单位分别映射 |
| 图纸、模型配置、工程 BOM 版本 | PDM/PLM；无则由授权技术员 | 文件 ID、模型配置、发布版本、哈希、行号及来源位置 |
| 制造 BOM、工艺路线 | 客户指定的 ERP/MES | EBOM→MBOM 关联、替代料、损耗、外协、工艺版本及审核状态 |
| 工序、工作中心、执行人员 | 已有 MES；否则KANPACE | 工种≠人员≠设备；技能、班组、班次分别映射 |
| 库存可用量与材料价格 | ERP/WMS | 缓存必须带查询时间、仓库与状态，缺少时标未知，不按零库存处理 |
| 工序报工、合格/报废/返工 | 唯一指定 MES/ERP | 一次实际动作一个事件 ID；更正走冲销/调整语义，不重复完工 |
| 采购下单、财务凭证、正式报价 | 原 ERP 与原审批 | KANPACE只输出获准对象/草稿；工艺估价不等于正式合同价格 |

尺寸统一以毫米计算并保留原单位；数量保留每套/整单口径。件、张、米、平方米、立方米、千克不能无依据互换。金额保留币种、含税/未税、舍入与价格日期。玻璃面积、板材面积、五金重量、灯带长度必须来自可核查尺寸/密度或原系统数据。

## 接口分层

```text
客户原 ERP / MES / PDM / WMS / 协同平台
     ↓ 官方 API / 事件 / SDK / 受控文件
客户网络内的连接器：凭据、版本适配、字段映射、同步队列
     ↓ KANPACE统一业务对象与审计记录
图纸来源 → 构件复核 → 工艺编译 → 版本发布 → 工种任务
     ↓ USB（已实测）/ 局域网 Wi-Fi（接入已实测，HTTP 派工待验）
ESP32-C3 工牌（已实现接收；报工事件规划中）

AI 助手 / CLI / MCP → 同一业务服务与授权校验 → 以上连接器
```

API 是系统读写的业务入口；Webhook/事件用于获知变化，需去重和补漏；SDK 简化某种语言的调用；CLI 适合脚本、批量作业与诊断。MCP 使模型发现并调用工具，不会自动补齐原系统没有开放的业务动作，也不会替代其权限。官方 MCP 规范定义工具调用及 HTTP 授权，因此可把已验证的业务服务包装成KANPACE自己的 MCP，明确标注为自建适配，不冒充原厂服务。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。

优先顺序：官方 API＋事件；其次官方 SDK/中间平台；再使用原系统支持的 CSV/XML/Excel 导入导出。RPA 仅用于确无稳定接口、客户允许且可核验的遗留流程。API 对接不直接修改 ERP 数据库。OPC UA、MQTT 等设备层通信即使可用，也不等于已经取得 BOM、销售单或报工接口。

## 连接器实现约束（设计，尚未编码）

连接器应按「厂商＋产品线＋版本＋部署方式」注册能力，而非给整个品牌一个支持勾。最小能力集合为 `probe`、`read_orders`、`read_items`、`read_bom`、`read_work_orders`、`read_stock`、`prepare_write`、`commit_write`、`get_write_status`、`read_changes`；每项分别标记 supported/unsupported/unknown、读写范围、版本和许可依据。

每条同步保留 `tenant_id`、`connector_id`、`source_system`、`source_object_id`、`source_line_id`、`source_revision`、`target_object_id`、`mapping_version`、`event_id`、`payload_hash`、时间与状态。复合身份避免不同账套的 SO-001 相撞。模型产生的拆单建议携带来源和置信不足项，不能把未经复核的推断写成已发布主数据。

使用本地事务 outbox/inbox 和持久化游标。事件重试按指数退避，遵循厂商限流；定时对账补足丢失事件。业务效果去重不等于传输只发生一次：遇到目标系统写入成功但响应丢失，先按外部事件键/单据关联查证，再重试；若系统无可查证的幂等机制，进入待处理，避免自动重复报工。

按来源版本或 ETag 校验并发，发现冲突显示字段差异。写回失败不把本地记录显示为「已同步」。更正或取消要遵循原系统撤销/冲销业务规则；已审核单据不靠覆盖数据库回退。

本地部署连接器主动访问云端 API；需要事件时由客户已有网关/iPaaS 或获准消息服务中转。默认不暴露当前单机服务到公网。若使用长连接或轮询，按厂商支持方式实现。客户网络中已购的 iPaaS 可承接映射与传输，KANPACE保留工艺和版本语义。

## 分阶段实施

| 阶段 | 可交付结果 | 通过条件 |
|---|---|---|
| 0：确认现状 | 产品/版本/模块/自定义字段/样单/权限清单；签定数据主责 | 明确哪边录入、哪边审批、哪边报工，取得官方契约和测试租户 |
| 1：只读订单与 BOM | 单一客户单一系统的可重跑映射；原编号与来源可追踪 | 代表性订单数量/单位/版本核对无差异；重跑不重复建单 |
| 2：拆单与草稿回写 | 经复核的 BOM/工艺/工单差异预览，回到原审批入口 | 原系统接受并返回真实单号；验证权限不足和版本冲突 |
| 3：现场闭环 | 原工单到工牌，再从真实操作事件回到唯一报工系统 | 重复事件不重复记账、离线恢复、旧版拒绝、失败可重试并对账 |
| 4：跨系统与智能入口 | 多账套映射、CLI/MCP 查询/建议/受控动作 | 每个动作沿用同一业务授权与审计，租户隔离和能力探测有效 |

优先级按已确认客户使用率、对象覆盖、许可可得性、技术实现成本排序，不能只按品牌知名度。未拿到客户实际系统前，可先用文件接口和 ERPNext 验证映射协议；国内付费试点优先挑已获得授权的金蝶云星空或用友 U8，一次做透一个。黑湖小工单先核对其自身开放契约，不能套用黑湖智造接口。

## 当前软件与后续开发的清楚边界

已完成：本地 Web、SQLite 持久化、BOM CSV/JSON 与有限 ASCII DXF 处理、原文件留存、人工复核、工艺生成/版本发布、人员与任务、文件导出、真实 USB 设备接收、Wi-Fi 扫描和 AP 接入。SolidWorks 原生文件需要相应 Windows 导出桥；目前不承诺通用几何推理。

尚未完成：任何真实客户 ERP/MES 认证连接器、正式外部业务 API 认证、订单增量同步、主数据编码映射、事件队列、报工回写、库存/采购闭环、KANPACE CLI/MCP 服务，以及原系统中的嵌入入口。调研页面的「官方接口证据」不等于KANPACE已接通。

当前 `GET /api/state` 等接口是本机单操作员 API；不能把它直接开放为企业多租户集成服务。设备协议已有独立身份和回执，也不能替代业务系统权限。后续先补业务边界，再实施首个真实连接器。

## 向客户或厂商一次收齐的资料

产品全名与版本/补丁；云端或本地；已购制造/库存/开放平台模块；组织与账套；API 基址、文档和沙箱；授权方式、许可费用及限流；已审核订单、含套数 BOM、工艺路线和报工样单；自定义字段/单位；谁负责审批与报工；外部事件键/幂等与查询能力；VPN/网络可达方式；原实施商联系人。凭据通过客户本地密钥配置提供，不写进聊天、共享文档或源码包。
